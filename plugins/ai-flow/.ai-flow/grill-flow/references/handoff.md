# 交接契约：新 session 先读什么 · 旧 session 走之前写什么

> **触发**：① `/clear` 之后入场（任何 stage）② 撞上 context 收尾阈值（`wrap_up_at_pct`）③ 开发者说要 clear
> ④ 一批票收口之后。
> `<FD>` = 本文件所在目录的上一级（定义层，随插件走：`stages/` `references/` `scripts/` 都在这儿）；`<FR>` = 项目里的 `.ai-flow/<flow>`（state 在这儿）。两个都给**绝对路径**：主 session 从 stage 提示词 `[ai-flow:paths]` 块的 `flow_def:` / `flow_root:` 行取；子代理用主 session 在派发 prompt 里给的那个。
> `<产物目录>` = `docs/<flow 名>s/<flow_id>/`
> （`flow_id` 用注入 context 顶部的实际值，勿自拼）。
>
> 这份契约管**「背景怎么传下去」**。它和各 stage 自己的重入判据是两件事，不互相取代：
> 那些判据回答「我在哪个物理状态」（stage-1 的 `wayfinder-map.md` 四态 · stage-2 的子产物
> 探测链 · stage-3 的 `reentry.md` 相位表 · stage-4 的 reset/HEAD 对照 · stage-5 的沉淀清单
> 重建），本文件回答「我该知道什么才不会做错方向」。⛔ 别拿本文件当相位判据用。

---

## 一 · 入场：交接段最前面必须能回答这八问

交接段活在 `<产物目录>/tickets.md` 的最开头（`## 🔴 重入交接`）。**它的第一块必须是一张
「要知道什么 → 切哪里」的表**，而不是一段叙事。每一格给**可复跑的命令**，不给行号（理由见
下面第三节第 1 条）。

| 新 session 要知道 | 表里必须有的一格 |
|---|---|
| ① 第一目标是什么、**明确不是**什么 | 一条切 `alignment.md` 的命令 |
| ② 什么不算兜底（哪些「防御」是履行契约、照写） | 一条切 `alignment.md` 的命令 |
| ③ 决策台账：**已拍板的** ＋ **问了但没答的** | 两条切 `spec.md` 的命令（`## Decisions` / `## Pending Decisions`，两个都是固定标题；⚠️ 后者**允许不存在**——本 flow 没出现过「问了但没答」时它就没被建过，那一格直接写「无悬置项」，⛔ 别为了让命令非空去编一节出来） |
| ④ 整体计划走到哪了、本轮接的是哪一段 | 只给**算法**，见下 |
| ⑤ 形状权威：字段名 / 类型 / 相位标识以哪份文档为准 | 按票取节，⛔ 别整篇带 |
| ⑥ 派子代理时**必须写死在 prompt 里**的边界纪律 | 逐条列出，不给指针 |
| ⑦ 主 session 怎么裁子代理回报（判断型 / 机械型分流） | 逐条列出，不给指针 |
| ⑧ **主 session 自己的行为纪律**：什么时候该问开发者、什么时候必须自裁 | 逐条列出，不给指针 |

⚠️ **③ 为什么是两节：「问过」和「拍板了」不是一回事。** stage-3 目前只要求「问过**并拿到结论**的」落进 `spec.md ## Decisions`。实测某条 flow 滚出 **9 条**「问了但开发者没答」的悬置项，它们全部只活在交接段的第五节里、`spec.md` 里**一条都没有** ⇒ 下一次 `/clear` 之后没有任何机制会把它们捡回来，于是被原样重新问一遍。⇒ 固定标题 `## Pending Decisions` 就是为收容它们新增的，第 ③ 格**两节都要带出来**。

⛔ **不要因此加第 ⑨ 问**——「八问」这个编号被别处引用着（`references/ask-before-asking.md` 里「落点是入场表第 ⑧ 格」那句就是），**扩格不扩数**。

⇒ 两节的处置**不同**，写交接段的人要把这个差别就地写进那一格，别只给两条命令：

- `## Decisions` = **已拍板**，照做，⛔ 别重开。
- `## Pending Decisions` = **悬而未决**。新 session 撞上同一个问题时，**先来这一节查「这个是不是已经问过、开发者当时没答」**——查到了就接着那里记的上下文走（补足信息再问、或按那里写明的默认值推进并标注），⛔ **别当成没问过、原样再问一遍**。重问一遍拿不到新信息（开发者当时没答的原因通常还在），却要烧掉一轮人在环的往返。

🔴 **⑧ 是 2026-09 补的，补它的原因本身就是它存在的理由：这一格的缺失在原来的七问框架下不可见。** 实测：某个 flow 的开发者定过一条流程规则——「不是必须开发者决策的问题，一律先派子代理对抗性审查主 session 的推荐，二者对齐就直接推进」——它落在 `alignment.md` 与 `spec.md ## Decisions` 里，而交接段只给了一个混在别处的指针。**派出去的冷读验证子代理报了 7/7 全通**，因为它答第 ⑦ 问时走的是「裁**回报**的判断型 / 机械型分流」那一节，而那与「何时该**问开发者**」是两件事；七问里没有任何一格指向主 session 自己的行为纪律 ⇒ **没有一个环节会去找它，缺了也不会有人报**。最后是开发者凭记忆问「那条指导思想是不是每个新 session 都会读」才暴露的。

⇒ 这一格至少要写全三件：

1. **判据**：「必须开发者决策」的定义是什么（通常是 `alignment.md` 里那张分类表）。⚠️ 判据是「这件事属不属于那几类」，**不是「主 session 有多不确定」**。
2. **不属于那几类时的完整动作**：先自己形成一个**带依据的推荐**（⛔ 没有推荐的对抗审查没有攻击面）→ 派 **fresh-context** 子代理**尽力推翻**它并**自己复跑取证** → **只有几个来回都收敛不了才问**，且要写清**攻不下来的那一点**。
   ✅ **允许它回「攻不动」，但必须交代怎么攻的**：写清**试过哪几个攻击角度**、**每个角度用什么命令 / 读了哪个文件哪一行取证**、**为什么没攻下来**。⛔ 禁的只是空洞的「基本同意，补充几点」——那种回报不含信息；**零结果本身合法**（`stages/stage-2.md` 的对抗性方案审查早就这么定：「即使无阻塞项也必须写该段」，记「已审查，无阻塞项」）。
   🔴 ⛔ **不许为了交差造反驳。** 「必须找出不同意见」这条指令会把子代理变成反驳生成器，而它造出来的反驳会被当成战果采纳——一个 99 分的方案就是这样被「优化」成 85 分的。⇒ 一份诚实的「攻不动 + 我试过这五条路」比一条硬挤出来的 finding 有价值得多。
   🔴 **依据不是口味，是公开实证**：没有外部信号时让模型自查自纠，性能不是持平而是**下降**（ICLR 2024《Large Language Models Cannot Self-Correct Reasoning Yet》，瓶颈名为 verification bottleneck——模型判得出一个回答得不得体，判不出自己的推理哪一步错）；多代理辩论的典型失败形态是**说服力压倒正确性**（《Talk Isn't Always Cheap》）；谄媚会在代理之间**传播**、互相强化偏差（《Too Polite to Disagree》）。⇒ **「几个 AI 都同意」不构成证据**：有案例是 80 多个代理一致背书一个根本不存在的漏洞，被一条测试一击杀死。
   **它的 finding 要不要合并，按下面三条判**：
   1. **每条 finding 必须带可复跑的取证**：一条命令 + 它的输出，或 `文件:行号`。⛔ **拿不出取证的一律不合并**，哪怕听起来很有道理——「听起来有道理」正是说服力压倒正确性的入口。带取证把推荐整条推翻的，就按它的结论走。
   2. **举证责任在挑战方；平局保留在位方**：双方都只有论证、没有取证时，**默认保留原方案**。⚠️ 没有这条默认值，每一轮只要挤得出一条「算是站得住一半」的意见，方案就被改一次，而且是**单向**的——那就是 99 分磨成 85 分的机理，每一步都看起来像在优化。
   3. **裁决方必须自己跑一条**：主 session 采纳任何一条 finding 之前，**至少亲手复跑它给的一条取证命令**。⛔ 不许只读论证就采纳——那裁决的是文采，不是事实。
3. **反向条款**：属于那几类的 ⛔ **不要先审一轮再问**——那只是延后开发者该拍的板，还多烧一轮。

⚠️ **派对抗审查时有三条实测纪律，漏了会让整轮结论作废**：
- **钉死 sha**，或在 prompt 里写明「回报里必须写出你实际读到的 sha」（后者实测有效）。**若主 session 正在往同一分支合票，基准会在子代理跑的过程中前进而它无从察觉。**
- **它给的「归属 / 落点」必须是真实存在的东西**。实测：某轮子代理给了四个**不存在的票名**当归属，那等于仍然无主。⇒ 归属只能由主 session 立票兑现。
- **回报必须给得出「枚举面」**：凡对抗审查，回报要能回答三件事——**你枚举了什么面、枚举了多少个、逐条结论是什么**。答不出枚举面的是意见交换，⛔ **不该有推翻权**。🔴 正面样本：某次收尾的安全专项把 base 与 HEAD 的 **429 / 392 个端点**（「方法 + URL」去重后）逐对比对了鉴权轨声明，**57 条字面差异全部核实归因**——那是枚举 + 逐条核实，所以它的结论站得住。

⚠️ **这三件的权威定义现在也在 `references/ask-before-asking.md`**（stage-3 岔路表「想停下来问开发者」那一格路由过去的就是它）。**两处都要有、且要同步**：定义层那份管「主 session 走岔路表时读得到」，交接段这一格管「/clear 之后的新 session 在入场表上看得见」。⛔ 任何一处都不许退化成指向另一处的指针——实测三处产物都写了、新 session 仍连着违反两次，正是因为它们都不在被真正读到的那条路径上。

⚠️ **①②⑤ 的标题名不在这份契约里写死，因为它们逐 flow 不同**（`alignment.md` 的段落结构由
stage-1 那一轮 grill 的走向决定，没有固定骨架）。写交接段的人**照本 flow 的 `alignment.md`
实际标题填图案**，并且**填完当场跑一遍确认非空**：

```sh
node <FD>/scripts/read-section.cjs --flow-dir <FR> docs/<flow 名>s/<flow_id>/alignment.md '<起始图案>' '<结束图案>'
```

⛔ 没跑过就别写进交接段——写错标题的那一格，下一个 session 拿到的是空输出或整片文件，
而两者都不报错（这正是 `read-section.cjs` 存在的理由）。

⑥⑦⑧ 三格是九批实战里最贵的错误来源（子代理误派、回报误裁、**该自裁的去问了 / 该问的自己拍了**），**它们必须在交接段里就地写全，
不许只放一个指针** —— 指针会被跳过，而这两类错误发生时不报任何错。

⛔ **④ 只写算法，不写快照。** 「下一批是 T40/T41/T42」这种句子每批都会过时，而它读起来仍然
像真的。批次怎么算已经在 stage 提示词和 `scripts/schedule.cjs` 里，交接段**指向它**即可，
⛔ 不要抄第三份。实测：某版交接段存了「B10 相位 + 下一批票号 + 进度百分比」约 130 行，
到 B13 时整段都是错的。

## 二 · 收尾：走之前把什么落下来

### 分两类，规则相反

⛔ **不要对全篇一刀切「重写」或「累加」。**

- **状态类**（当前相位 · 进度数字 · 下一步做什么 · 在飞的树和代理）⇒ **整段重写**。
  它们的正确性随批次变化，累加就是锚点腐烂。实测：一份交接段从 884 行重写到 837 行、
  评审待办段从 68 行压到 25 行，是健康的；另一次删掉 111 行过期快照同样是。
- **教训类**（已拍板决策 · 边界纪律 · 裁决流程 · 「已核实过别再纠结」的结论）⇒ **只增不删**。
  重写时**必须逐条核对「这一条在新版里还在不在」**。
  ⚠️ 实测反例：某次精简重写之后，「⛔ 别整篇 Read 本文件（约 640KB，你只用得上约 10%）」
  这条自保护提示**消失了**，直到下一次冷读才补回 —— 重写确实会丢东西，这个核对不是形式。

### 锚点必须可推导

🔴 **凡是「下一个 / 当前」这类指向，写成能算出来的形式，不许硬编码票号。**
实测同族三处：切读指引长期写着「下一张要做的票（T12）」而 T12 早已完成 ⇒ 新 session
第一步就去切一张做完的票；`## 收口记录` 段停更在 B3；派发骨架里的例子全是某张具体票专用的。

### 切读图案必须与格式无关，并且**断言非空**

图案依赖的是文件**格式**，而格式会随文档增长而分叉。实测：`ledger.md` 的缺陷条目前 34 条是
表格行（`| N33 | … |`）、N35 以后不是 ⇒ 教人用的 `grep -n '^| N5 ' ledger.md` 对 N35+
**零命中且不报错**，而两张票点名的 N45 / N51 恰好都在那一段。

⇒ 优先用与格式无关的写法（词边界 `grep -n "\bN45\b"` 而不是行首图案），并且**用带断言的封装**：

```sh
node <FD>/scripts/read-section.cjs --flow-dir <FR> <文件> '<起始图案>' ['<结束图案>']
# 零命中 → 退出码 1 并打印「图案很可能已经漂了」，不会给你一个静默的空输出
```

### `/clear` 会带走什么

flow 状态和已 commit 的东西在磁盘上，活得下来。**在飞子代理的回报活不下来** —— 它的
findings、真机待验项、安全自检，从它留下的那笔 commit 里重建不出来。
⇒ **有代理在飞就等它回来。** ⚠️ 它的产出大部分在回报里、不在树里 ⇒ 工作树干净时「摘树状态」
什么也摘不到，⛔ **别把「树是空的」读成「它还没产出、走了不亏」**——那恰恰是必须等的情形
（存活性判据见 `subagent-lifecycle.md` §三 第一条：完成通知还没到 = 它还在跑）。只有树里真有
未提交改动时，「先把那棵树的状态摘进交接段」才替代得了等回报。

🔴 **但回报并非不可挽回**：`/clear` 丢掉的子代理回报可以从磁盘原样找回，不必重建、也不必
派人复审 —— 落点是 `~/.claude/projects/<把 cwd 的 / 换成 - 的目录名>/<session-id>.jsonl`，
回报正文在 `task-notification` 的 `<result>` 里。实测一次质量链回报（含两条待裁 finding、
`qc-metrics`、7 条真机项）就是这么全量恢复的。

### 冷读验证：按触发条件做，不是每次都做

**一个 `/clear` 后的新 session 冷读走一遍，是唯一能测出「交接段够不够用」的手段** ——
grep 抽查一致性测不出来，因为它不会照着指引真的走一遍。实测两次都抓到了真错误：一条
「旧树冻结」的假约束已经活过至少一次 `/clear` 周期；一处写死票号的图案零命中且退出码 0。

但它不便宜（实测九次开发者驱动的收尾累计约 162 分钟、12 个子代理，最贵的两次各 53 / 47 分钟）。
⇒ **触发式**：满足任一条才派 fresh-context 子代理冷读，两条都从 git 算得出来 ——

```sh
# ① 本轮交接段改动超过 30 行
git diff --numstat HEAD -- docs/<flow 名>s/<flow_id>/tickets.md
# ② 本轮改过 alignment.md 或 spec.md（决策台账所在）
git diff --name-only HEAD -- docs/<flow 名>s/<flow_id>/{alignment.md,spec.md}
```

⚠️ **这里原本还有一条「距上次冷读已过 N 批」——已删除，因为「上次冷读发生在第几批」没有任何
地方记录**，flow 状态、票面、脚本里都查不到，它按本文件自己的标准就是不可执行的。真要这条，
得先给它定一个落盘字段；在那之前上面两条已经覆盖了主要风险（交接段大改、或指导思想/决策变动）。

其余情况用机器断言顶替：对交接段里每条切读命令跑一遍 `read-section.cjs`，**全部退出码 0** 即可。

### 收尾做完了怎么算

- 交接段**每一问**——即第一节 `## 一 · 入场` 那张表的**全部格子**——都能从表里走到答案（自己按表切一遍，命令全部非空）
  - ⛔ **别在这里抄问题条数。** 上一次那张表扩格（补 ⑧）之后，这一条自检仍写着「七问」，**而这类漂移不会有任何东西报错**：没有脚本、测试或退出码在核对「自检里的数字」和「表里的格子数」对不对得上——和上面 ⑧ 被漏掉是同一种漏法（没有任何环节会去找它）。⇒ 自检只引用那张表本身，条数由表决定。
- 状态类已整段重写；教训类逐条核对过没丢
- 在飞代理要么已回收，要么其树状态已摘进交接段
- 告知开发者可以 `/clear`
