# 旁路修复：本期之外的问题，现在就想修

> **触发**：执行中（stage-3）或收尾人审 / 真机验证中（stage-4）发现一个**与本期需求无关**的问题，开发者说「顺手修了」。
> `<FD>` = 定义层（`scripts/` `references/` 在这儿）；`<FR>` = 项目里的 `.ai-flow/<flow>`（`state/` 在这儿）。两个都取绝对路径，来源见 stage 提示词的 `[ai-flow:paths]` 块。

**与 `mid-flight-ticket.md` 的分界**：那份管「本期**还需要**一张票」——新票属于本次需求。这份管「这事和本次需求无关，但现在就想修」。判据不是感觉，是下面第一步。

## 第一步：写集相不相交（先算，再动手）

「无关」只有一种能被机器判定的含义：**这笔修复要改的文件，和本期要改的文件不相交**。先把它的写集列出来（就是普通票 `Touches:` 的同一套写法），再按当前 stage 取本期的写集：

| stage | 本期写集怎么取 |
|---|---|
| stage-3 | tickets.md 里**全部**票的 `Touches` 并集（含未勾的——它们还没做，但会改） |
| stage-4 | **review.md 里记下的「本 flow 代码改动范围」**（环节 C 在 reset 前写的那份 `git diff --name-only <base>..HEAD`）∪ 已勾票的 `Touches` 并集 |

- **不相交** → 走下面「旁路」。
- **相交** → 走下面「并入本期」。**这是默认，不要停下来问开发者**。相交意味着这笔修复和本期会改同一批文件，硬拆出去的代价是最后合并时必然撞车，而那时才发现就晚了。

⚠️ **相交判定用真实路径，不要用「感觉相关不相关」**。一笔改在 `utils/date.ts` 的修复，和一张声明 `Touches: utils/**` 的票就是相交，无论它们在语义上多么无关。

⛔ **stage-4 下不要拿 `git status` 当本期写集**。环节 C 已经 `git reset <base>` 把整轮改动摊成未暂存全量，而你这笔修复**也在那一堆里**——用它判定，永远得到「相交」。要判的是「本期**有没有动过**这些文件」，那个答案在 review.md 的范围记录和已勾票的 `Touches` 里，不在工作区现状里。

## 并入本期（写集相交）

**stage-3**：按 `mid-flight-ticket.md` 插一张票，全部规格照那份走（票面、机器门重跑、排进执行序列）。**额外只多一件事**：在票面标题里写清它来自旁路发现，并在下面的记账段记一行。

**stage-4**：改动就留在工作树里，随环节 C 的 squash 一起进。**额外两件事**：

1. **squash commit 的 body 加一行** `side-fix: <一句话说清修了什么>`。理由：它会和本期功能压进同一笔 commit，PR 评审看到的 diff 里有一块解释不了的改动——这一行是他唯一能知道「这是有意并进来的、不是手滑」的地方。
2. 记账段记一行（格式见下），去向写「已并入本期 squash」。

⛔ **不要因为「它并进来了」就省掉质量链**。它和普通票同一套：改完照样跑该跑的评审与测试，只是不再单独 commit。

## 旁路（写集不相交）

分支从 **`base_sha`** 开叉（`<FR>/state/active.json` 里那个，`<flow> start` 时记的干净基线），不是从需求分支——从需求分支开叉的树会驮着本期全部改动，那笔修复的分支和它将来那个 PR 就不再只含这一笔。

### stage-3

```sh
node <FD>/scripts/worktree.cjs --flow-dir <FR> open <flow_id> S1 --base <base_sha>
```

然后**和普通票完全一样**地做：派实施子代理（`per-ticket-review.md`）→ 派质量链子代理（`quality-chain.md`，三评审 + 注释清理）→ 在那棵树里 commit。做完：

```sh
node <FD>/scripts/worktree.cjs --flow-dir <FR> park <flow_id> S1
```

`park` 不是 `close`：它跑完「树干净 / 有 commit / diff 非空」三条断言就拆树，**分支留着，不合进任何地方**。⛔ 不要对旁路树用 `close`——那会把它 ff 进需求分支，等于混进本期 squash，旁路的全部意义就是别这么做。

### stage-4

和 stage-3 有一处关键不同：**修复此刻已经在主工作树里**（环节 C 的人审-修复循环就在工作树里改）。所以顺序是「当场判定、最后搬运」：

- **发现时**：按第一步判完相不相交。不相交 → 改动**照常留在工作树里**，在记账段先记一行（去向暂写「待搬」）。留着是有意的：环节 C 后面还有真机验证，把它摘出去，开发者验的那个构建里就没有这笔修复了。
- **搬运时机**：`git add -A` 之前的那次 **squash 前工作树 scope 核对**（stage-4 提示词里那一步）。那一步本来就要逐条过 `git status --porcelain` 决定什么进 squash——旁路修复就是「不进」的那一类，原先那条路只写到「停下问开发者」，现在它有答案了。

搬运四步，**顺序不能换**（先落到分支上，再从主树摘掉）：

```sh
# 1. 开一棵 base 上的干净树
node <FD>/scripts/worktree.cjs --flow-dir <FR> open <flow_id> S1 --base <base_sha>

# 2. 把这几个文件的改动搬过去。<paths> 是这笔修复的写集，逐个列出，别用通配
git diff HEAD -- <paths> > /tmp/side-S1.patch      # 已暂存的也要算上，所以比的是 HEAD
cd <worktree 根> && git apply /tmp/side-S1.patch    # 在树根跑：patch 里的路径是 git 根相对
```

⚠️ **新增的未追踪文件不在 `git diff` 里**。先 `git status --porcelain -uall -- <paths>` 看有没有 `??` 行，有就单独复制过去（`cp`），漏了它 patch 会静默少一块，而 `git apply` 照样 exit 0。

```sh
# 3. 在树里走质量链（和普通票同一套）→ commit → park
node <FD>/scripts/worktree.cjs --flow-dir <FR> park <flow_id> S1

# 4. 确认 park 打印出了分支与 commit 之后，才回主树摘掉这几个文件
git checkout -- <tracked paths>     # 已追踪的：恢复成 base 的样子
rm <untracked paths>                # 第 2 步复制走的那些
```

⛔ **第 4 步在第 3 步成功之前一个字都不许敲**。`git checkout --` 对未暂存改动是不可逆的，此刻它还是这笔修复的唯一副本。

⛔ **第 4 步之前再核一遍写集**，别只信第一步：拿 `<paths>` 逐个去比 review.md 的范围记录 + 已勾票 `Touches` 并集，**命中任意一个就停手**。整文件 `git checkout --` 恢复的是**这个文件的全部未暂存改动**——文件里若还有本期的改动，它们一起没了，而且此刻本期的改动还没有任何一笔 commit 兜着（环节 C 的工作区就是唯一副本）。这是本文件唯一一处能造成不可逆数据丢失的地方。命中了说明第一步判错，改走「并入本期」。

## 记账：`tickets.md` 的 `## 旁路修复` 段

**每一笔都要记**，不管走的是哪条路。`/clear` 之后 tickets.md 是唯一真相源，不记它就从 stage-4 的收口、stage-5 的知识沉淀和交接文档里彻底消失。

段落位置：票列表区**之后**，和 `## 待真机验证` / `## 已知碰撞面` / `## 收口记录` 并列。条目格式（**非复选框**）：

```
## 旁路修复

- S1 修掉设置页保存后不刷新 — 写集: apps/desktop/src/settings/save.ts — 去向: sidefix/2026-09-18-15va-S1 @a1b2c3d
- S2 日志时间戳少了时区 — 写集: packages/log/fmt.ts — 去向: 已并入本期 squash（与 T4 写集相交）
```

⛔ **不要写成复选框**，也**不要在这个段里写票号**（`T<n>`）。两者的后果不同，都要知道：

- `- [ ] S1 …`：机器门看不见它（它只认 `T\d` 形态的 ticket 级行），所以不会报错——但它也就不是记账，谁都不会去读一个看起来还没做完的复选框。
- `- [x] T9 …`：**会被当成一张真票**，门于是去 `base..HEAD` 找属于它的 commit，报「已勾 ticket 没有自己的 commit」——方向完全对不上，排查要绕远路。`gate-stage-3.cjs` 现在会就地拦下并说清原因。

## 收口时还要做的两件事

- **stage-4 的完成条件里那条 `git branch --list "wt/<flow_id>-*"` 为空，不包含旁路分支**——它叫 `sidefix/…`，正是为了躲开那次清理。⛔ 别顺手把它一起删了：它承载的修复还没合进任何地方。
- **告诉开发者去向**：每条旁路分支都要在收口汇报里点名（分支名 + 一句话），让他决定是单独发 PR 还是本期合完再合。⛔ 不要替他 push，也不要替他合。
