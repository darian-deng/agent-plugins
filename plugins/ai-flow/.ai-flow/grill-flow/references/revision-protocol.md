# 前置产物修订协议

> 中后期 stage 发现「前面已对齐的东西要改」时统一走本协议。两个入口，汇入同一套影响评估。grill-flow 产物链：alignment.md（stage-1）→ spec.md + tickets.md（stage-2）→ 代码 + candidates.md（stage-3）→ review.md（stage-4）。

## 触发入口

### 入口 A — 开发者异议
开发者对当前 stage 产出有异议。**先判是否成立，不反射性接受**（"You're absolutely right"、立即改、表演性同意都是失败模式）：

| 类型 | 描述 | 处理 |
|------|------|------|
| A 事实约束 | 指出 AI 没考虑的事实约束 | 接受 |
| B 纯偏好 | 给不同写法但没理由 | 不接受，要真实考量（时间/历史/风险）；"感觉更好"不收 |
| C 冲突已有决策 | 与已记录决策冲突 | 逐项过，成立 → 影响评估 |
| D 推翻前置结论 | 推翻前置 stage 已对齐结论 | 影响评估 |

### 入口 B — AI 自查
AI 自查发现前置产物漏写/错了。直接进影响评估。**禁止自判后默默改。**

## 影响评估

### 1. 分级

| 等级 | 触发 | 应对 |
|------|------|------|
| **L1** | 推翻已对齐核心决策 / 范围 / User Story | **stop**，呈现问题 + 建议 abort，理由说清；确认后重 `grill-flow start`。 |
| **L2** | 漏一个约束/seam/US 子项，不推翻已有决策 | 暂停，回改对应上游产物，开发者确认后再继续 |
| **L3** | 局部命名/措辞/显然遗漏 | inline 修为当前态；按下方暴露纪律当场告知，不嵌进产物正文 |

### 2. 上游产物影响回溯（关键）
按当前 stage，逐一审视**全部**已产出的上游产物（alignment.md / wayfinder-map.md / spec.md / tickets.md / 已 ship 代码 / review.md），受影响的**全部同步更新**。绝不允许"上游停留旧决策、当前产出已是新决策"的分裂状态——/clear 后任何子代理会拿到分裂的真相源。

**回改一律覆盖为当前态**：产物正文改成新决策即可，**不留"原本…改成…"演化叙事**（回溯交给 git diff）。

### 3. 下游兜底
在 stage-3 触发、且 L2 改了 spec/tickets → grep 已完成 ticket（`[x]`）的改动文件，评估是否需就地在 tickets.md 追加/重切 ticket。不允许"改了 spec 但不修已 ship 代码"。

### 4. 暴露纪律 + gate 无 reject
- **L1/L2 必须停在当前位置等开发者确认**，禁止继续推进。
- **L3 禁止默默改**，在 gate 前审查清单或（无 gate 的 stage-3）当场告知。
- **gate 无 reject 语义**：开发者不批 gate ≠ 引擎回退。只能"继续讨论 → 就地改产物（spec/tickets/findings/代码）→ 重新呈现 → 再 approve"，或 abort 整个 flow。
