# 车道模式（一组一车道）：动作差异与代价

> **触发**：`execution-unit.md` 算出该走车道模式。本文件是车道模式下与 stage-3 主循环**不同**的全部动作；没提到的一律照主循环。
> `<flow_root>` = 本文件所在目录的上一级；stage-3 提示词里 `{{flow_root}}` 展开出来的就是它。

## 代价三条，都要接受

### 1. 机器门⑦ 对它不生效 → 必须自己记「已知碰撞面」

并行的票分布在不同车道、不落同一个 `batch:`，所以「同批实际写集不相交」这条查不到它们。⑥（每票实际改动 ⊆ 它声明的 `Touches`）仍逐票生效，所以「按 `Touches` 不相交准入 + ⑥ 核实际」这条链还在；丢掉的是「两票同时改同一文件的不同区段、rebase 也不冲突、于是交界面无人复核」这一种。

**处置（必须落盘，且落盘时机是每票 close 之后，不是收尾时回忆）**：每票 close 成功、做那份记账时多做一步，⛔ **这一步与 `rm:pending` 同级、必须排在 `qc:done` 之前**（理由同 `rm:pending`：`qc:done` 是重入相位表的锚，排在它之后的记账一旦在两者之间 /clear，就会被「有 `qc:done` 无 `[x]` → 补勾」这条路径永久跳过）——把该票的实际改动文件（`git show --name-only --format= <该票那笔 sha>`）与**别的车道**已回合票的实际改动文件取交集。有交集就往 tickets.md 的 `## 已知碰撞面` 段 append 一行：

```
- <文件路径> — T<a>（R1）× T<b>（R2）：各自改了什么
```

**段标题用这个字面量**，stage-4 按它来找；本 flow 一次碰撞都没有时也要建这个段并写一行 `- 无`。⛔ 这个段要建在 `## 待真机验证` **之外**（那段里出现任何复选框写法都会让机器门直接 fail）。收尾时由 stage-4 组装审逐行点名。

### 2. 收口测试按轮，记账按票

收口测试（主循环第 6 步）的存在理由是「归并之后这棵树没有人验过」，而车道各自的节奏不同步时「谁负责验这棵树」就没有落点。所以一轮 = 每条活跃车道各做一票，**本轮全部车道都回合完**才跑一次收口测试。

- **快车道做完本轮那票后可以立刻续派下一票**——它跑的时间正好覆盖慢车道，不算破屏障。破屏障的是「跳过收口测试直接开下一轮」。
- **硬上限：距上一次收口测试已有 ≥4 票回合、或已过 ≥2 小时 → 无论各车道进度如何，立刻停派、跑一次收口测试并把欠的记账补齐。** 这条是给「轮」在长跑中溶解兜底的：实测一次连续 **11 票、6 小时 35 分**既没跑收口测试也没记账，而记账里的真机项与沉淀候选只活在主 session 的上下文里，那段时间任何一次 `/clear` 都会把它们全部丢掉（真机项丢失是静默的——stage-4 的完成条件是「`## 待真机验证` 无 `rm:pending` 残留」，空清单天然满足）。
- **这两个计数器必须落盘**：跑完一次收口测试，立刻往 tickets.md 的 `## 收口记录` 段 append 一行 `- <ISO 时间> — 覆盖到 T<n>（全绿 / 修了什么）`。硬上限按这条记录算——最后一条记录之后新增的 `qc:done` 已达 4 条，或该行时间戳距现在 ≥2 小时，就停派去跑。不落这一行，两个计数器只活在你的上下文里，**而这条规则要兜的正是长跑 + /clear**；段里一条记录都没有 = 从 base 起就没跑过，立刻跑一次。
- **记账的触发点仍是「该票 close 成功」，不是「本轮结束」**（主循环第 6 步）。

### 3. 长驻树会积累两类假红

树是长驻的，`sync` 只 rebase 代码；几条车道又在同一台机器上抢 CPU。**依赖漂移**和 **CPU 争抢**都会把正常的树报成大规模回归。两者的判据、区别、以及「别去读代码」的界线都在 `recovery.md` 的「先判是不是假红」——测试一红先读那节。

`worktree.cjs` 的 `sync` / `close` 现在会自己检测并补装依赖（带进 lockfile / `package.json` 改动时；`--no-install` 只报不装），所以这件事不再需要你记——但**你自己手动 rebase / 切分支之后不会有人替你装**。

## 动作差异（其余照主循环）

- **分组是你在这里算的，不是 stage-2 的产物**——tickets.md 只有 `Blocked by` 与 `Touches`，没有分组字段。算法：把「有 `Blocked by` 关系」或「`Touches` 相交」的票视作连通，取**连通分量**；分量多于车道数时按「**大分量优先放进当前最小车道**」装箱——**这就是 `schedule.cjs` 算轮数时用的那套**，换一套合并方式会让脚本那句「N 轮 < M 轮」的结论对你不成立。车道数取脚本用的 `--cap`（默认 3）。算完立刻落 `lane:`，**之后一律读它、不重算**——重算会在 /clear 之后算出不同的分组。
- 记账字段用 `lane: R<n>`（和 `qc:done` 同一口径，写在票行或其缩进子项）。⛔ **不要写成 `batch: R1`**——同车道的票必然写集相交，机器门⑦ 会把整组报成违规。
- 开车道：`node <flow_root>/scripts/worktree.cjs open <flow_id> R<n>`，每组一次、不是每票一次。
- **派发之前先落 `wip:`**：选定该车道下一票后，在**该票那条**写 `wip: R<n>`（与 `qc:done` 同一口径：票行内或其缩进子项），写完再派发；记账时删掉它（`qc:done` 落下即代表不在飞）。**没有它，「在飞」就无法从落盘状态判出来**——子代理从派发到 commit 之间车道分支毫无变化，而重入判据把「车道分支上没有未回合 commit」读成「下一票还没派」，于是同一棵树会被派进第二个子代理，或者另一条车道取走与它写集相交的票。（机器门不解析这个字段，多写一个子项不会触发任何断言。）
- **车道取下一票 = 该车道内文件顺序中第一张「`Blocked by` 已满足 ∧ 与所有在飞票 `Touches` 不相交」的票**，不是机械地取下一张。头票被挡住时**往后找**，都找不到才让这条车道空转。在飞集合 = 有 `wip:` 的票 ∪ 各车道分支上有未回合 commit 的那一票，两者都可从落盘重算，所以 /clear 重入能算出同一结果。实测不跳过的代价：一条车道因为头票被挡整整停了 54 分钟，而它名下还有五张够格的票。
- **一张票的 `Touches` 横跨多条车道的地盘时（「跨车道票」），它一开工就会挡住那几条车道**——把它排在各车道同时空闲的时刻单独跑，别在别的车道正跑时插进来。**落完 `lane:` 之后再跑一次 `node <flow_root>/scripts/schedule.cjs`**，它会点名这类票：跨车道相交校验只在分组来自 tickets.md 的 `lane:` 字段（且**每张**票都有该字段）时才做——选执行单位时跑的那一次还没有 `lane:`，走的是连通分量分组，按定义不可能报出跨车道相交。实测一张这样的票挡住另外两条车道共 133 分钟。
- **每票开工前先 `node <flow_root>/scripts/worktree.cjs sync <flow_id> R<n>`**：别的车道回合过之后本车道就不再是 HEAD 的直接后继，不 rebase 会在 close 时报「不是直接后继」。`sync` 会顺带把别的票带进来的依赖清单改动补装掉。
- **每隔 15 分钟扫一次 `worktree.cjs status <flow_id>`**，别只靠通知驱动。通知是**一次性**的：它已经来过、而你读错了，就不会有第二条来纠正你——那正是实测空转 1 小时 07 分的机制。判据在 `status` 的**静默**列：**一条声称在飞的车道静默 ≥30 分钟 = 那个子代理已经停了**（工作树的物理变化是唯一不依赖自我报告的信号），照 `subagent-lifecycle.md` 去唤醒它。
- **随时可以 `node <flow_root>/scripts/worktree.cjs status <flow_id>` 看全局**：一屏列出各车道的 `ahead / dirty / 是否 HEAD 后继 / 待补依赖 / 静默时长`。这张表原先只活在你的上下文里，靠记忆维护它的代价实测是漏 sync 的往返、六次依赖陈旧假红，以及一次把验证和 close 串成一条命令链导致地板红的票被 ff 进主分支。/clear 重入判相位时先跑它。
- 回合：`node <flow_root>/scripts/worktree.cjs close <flow_id> R<n> --keep`（前置断言照跑、ff 照做、树留着）。**本组末票去掉 `--keep`** 让树真拆——忘了是 fail-closed，机器门⑤ 会拦「未收口的 worktree」。
- 主循环第 4 步「回合之前裁完子代理回报」这条纪律不变，但理由换了：车道模式下树没拆、还能进去改，可该票那笔 commit 已经 ff 进需求分支，再改只能另提一笔——一票一 commit 就破了。

## 推进下一票前的自检（替代主循环那两条）

树按设计长驻到本组末票、快车道允许提前续派，所以主循环里「worktree 已全部拆除」「本批每票都回合完」两条不适用，**别因此把整条自检判成作废**。车道模式下自检这四条：

- 已 close 的每一票都有 commit + `qc:done` + `[x]`；
- `worktree.cjs status <flow_id>` 里没有「空闲却 `dirty:YES`」的车道（那是有改动没人认领）；
- 无未裁决的决策 / 安全项；
- `## 收口记录` 满足上面那条硬上限。

## 收口测试后如果做过 fixup rebase

`recovery.md` 第三节那条 `GIT_SEQUENCE_EDITOR=true git rebase -i --autosquash --autostash <base_sha_code>`（收口测试真红时用的）重写了需求分支上 base 之后的**全部** commit，于是所有长驻车道的基线同时作废。所以：

1. 跑那条命令**之前**先确认没有在飞的票（有 `wip:` 的等它 close，或让它先停在 commit 之后别 amend）；
2. 跑完**立刻**对每条车道各跑一次 `worktree.cjs sync <flow_id> R<n>`；
3. 再用 `worktree.cjs status <flow_id>` 确认全部车道「是否HEAD后继」都是 yes 才继续派发。

跳过这一步的表现：下次 close 报「不是直接后继」（响亮），或者在作废基线上跑出来的绿地板（静默）。

## 重入

车道模式的相位判定与一票一树不同（树是长驻的，「树存在」不等于「在飞」）——见 `reentry.md` 的「车道模式的重入」。
