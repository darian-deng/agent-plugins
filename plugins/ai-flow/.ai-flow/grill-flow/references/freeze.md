# 冻结面：开发者叫停某类工作时，怎么让它只停该停的

> **触发**：开发者要求「X 验通之前别开 Y」「先别碰 Z」「这批先停」；或某条决策把一组票的解冻条件系在一个还没发生的事件上（真机验收、外部依赖、另一条 PR 合入）。
> `<FR>` / `<FD>` 的取法见 stage-3 岔路表头。

## 为什么是票面字段，不是一段话

实测一条真实 flow：09-24 开发者拍板「切片①真机通过之前不开任何新切片首票」，主 session 把它写成 tickets.md 里的一段散文「切片冻结令」。此后 **B19–B33 连续 15 个批次全是单票**，frontier 三次清零共空等约 12 小时；09-28 开发者自己改成「不依赖深链结果的票解冻、骨架票禁碰 host/boot/preload/renderer」，**立刻 3 票在飞**——而这些 Touches 09-24 就全在票面上。差别不在开发者的意图，在表达：散文冻结令只能被读成「整片停摆」，`schedule.cjs` 的够格判定看不见它，`missed` 照样把冻着的票列成「够格」，主 session 每轮都得自己记着哪几张其实不能开。

所以冻结令是 tickets.md 的一个段、`schedule.cjs` 的一个输入：

```md
## 冻结面

- F1 — 解冻: 切片① 真机通过（T47 AC4 + T45 AC3 在同一次 pnpm dev 跑里通过）
  - paths: src/main/host/ src/main/boot/ src/preload/ src/renderer/
  - except: T45 T47 T48 T50 T51
```

- `paths:`：写集与之相交（目录前缀语义，与并批判定同一套）的未勾票被冻。
- `except:`：这些票不受本条冻结——**解冻条件自身的关键路径必须在这里**（切片① 的修复票都碰 boot/，不写 except 会把解冻条件本身冻死）。
- `only:`：只考虑这些票（票级停令用它：「T17 T41 先别开」= `only: T17 T41`，可不写 paths）。
- `lifted: <日期>`：已解冻，本条整段忽略。⛔ 不要删条目——它是「当时为什么停」的记录。
- ⚠️ `Touches: none` 的票**不按路径冻**（预估不了写集 ≠ 一定撞冻结面）；要冻它就写进 `only:`。

`schedule.cjs missed` 会把被冻的票单列成「❄️ 冻结面 F1 冻住 N 张」并从够格清单里排除；`stop-guard.cjs` 在 frontier 被冻空时会告诉你这是等门期而不是停点。

## 开发者下停令的那一回合：同一条回复里做完三件事

⛔ **不要单方面翻译**（把「别开新切片」擅自改成一组路径，等于推翻他的知情决策），**也不要另起一轮问**（那是又一次停顿）。在**同一条回复**里：

1. **把停令写成上面那种冻结面条目并落进 tickets.md**——按你对他意图最忠实的理解：他说的是切片/票 → `only:`；他说的是「别碰某块代码」→ `paths:`；两者都有就都写。`except:` 放解冻条件自身的关键路径。
2. **把这条冻结面原样贴给他看**，附一句机械后果：「按它，此刻够格 N 张（T…），冻住 M 张（T…）」——数字从 `schedule.cjs missed` 取，不要自己数。他不纠正就照此跑；纠正了就改条目，不重新讨论。
3. **列等门期工单**（下一节）并当回合开始做第一项。

⛔ 授权类决策（D-META-*）里**不许出现**「frontier 只剩冻结票时停下等开发者」这种句子——实测一条这样的边界让开发者刚说完「不要停下来问」两小时后，session 停了 326 分钟。frontier 被冻空的处置是等门期工单，不是停。

## 等门期工单（frontier 被冻空、且没有别的在飞时，按序做）

1. **细化下一切片的粗票**：补机器可跑的 AC、收窄 `Touches`、拆掉「等首票交付才知道有几张」的依赖（实测 S18 由主 session 提前细化省了一轮）。用只读子代理做，不碰代码。
2. **为冻结票预落**：AC 命令、`Touches` 收窄、`Blocked by` 类型核对（是代码依赖还是只是切片顺序）。
3. **跑欠的收口测试 / 整仓 typecheck**，把 `candidates.md` 里已能收口的条目收掉。
4. **核解冻条件**：它是不是已经满足了、或有没有一部分能由你自己跑（真机跑的机器判据、日志三条）——满足就写 `lifted:` 开票。
5. 以上一件都没有 → 用 Write 写 `<FR>/state/hold`，一行写清冻结面 id、解冻条件、等谁做什么。这才是合法的停。

## 解冻

条件满足 → 在那条冻结面下加 `- lifted: <日期> <一句依据>`，跑一次 `schedule.cjs missed` 确认那些票回到够格清单，按主循环开批。解冻是机械动作，不问。

## 把已有的散文冻结令迁过来

tickets.md 里已经有「🔴 切片冻结令」之类段落的：读它，按上面格式写一条冻结面（散文里点名的票放 `only:`，点名的路径放 `paths:`，解冻条件抄进 `解冻:`），在散文段末追加一行「⇒ 已转成 `## 冻结面` F<n>，以那条为准」。散文段本身留着当记录。
