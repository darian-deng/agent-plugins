# 执行期插票：本期还需要一张票时怎么办

> **触发**：stage-3 执行中发现「本期还需要一张票」——新暴露的缺口、刚交付的东西有缺陷、上游清单枚举不全。
> `<FD>` = 本文件所在目录的上一级（定义层，随插件走：`stages/` `references/` `scripts/` 都在这儿）；`<FR>` = 项目里的 `.ai-flow/<flow>`（state 在这儿）。两个都给**绝对路径**：主 session 从 stage 提示词 `[ai-flow:paths]` 块的 `flow_def:` / `flow_root:` 行取；子代理用主 session 在派发 prompt 里给的那个。

**照下面办，不要现编。**

## 谁能插

只有主 session。子代理发现要多做一件事 → 回报，不自行扩范围。

⚠️ **子代理回报里的「请开票 / 建议另立」是候选，不是结论**：它看不到台账里别的票，判不了下面的四查。照单全收就是一天 17 张新票的来路（实测 2026-09-21-mthu T351–T367：9 张源于回报里的明确请求，另 3 张回报给了「续派本票 / 开小票」二选一、主 session 都选了开票）。

## 立票前四查（先查，再立；⛔ 跳过直接写票）

**为什么**：一张票的固定开销约 17 万 token、两个子代理、一次 sync 与一次 close，与改动大小几乎无关（实测台账改 2 格 diff 4 行，实施 74k + 质量链 96k token）。所以「这件事要做」≠「这件事要一张票」。

**按序查，命中即停**：

- ① 有无**未开树**的票，其 `Touches` 已覆盖这次要改的文件、且同一域 / 同一不变量 ⇒ 在那张票加 `📥` + 一条 AC（必要时扩 Touches），⛔ 新票。
- ② 有无未开树的票与这次改动**同一前置**（`Blocked by` 相同、反正要串行）**且耦合**（同一不变量，或前一张改完后一张才好改）⇒ 同上并进。⛔ 只经汇聚文件（启动装配总表、rpc 命令表、能力台账、生成物、不变量文档这类多张票都写的文件）相交不算耦合，也不构成「并进同一票」的理由——同文件不同区段由 stage-3 `shares:` 放行；追加型（日志 / 注册表 / 清单 / 台账）不放行、只能排队（`stages/stage-3.md`「同文件放行」），排队也只是先后，⛔ 照样不构成并票理由。（以文件交集代替耦合判断，与 `stages/stage-2.md`「耦合的改动仍然应该切进同一票」方向相反：实测一张门禁脚本票与两张同前置的票只经架构总文档相交，按「相交即并」会被错并，它实际与其中一张并行做完。）
- ③ 改动 ≤ 10 行且属本票刚引入 / 刚查出 ⇒ 让本票在 close 前收回（复派形态丙）。
- ④ 这件事本来就在本票 `delivers` 里、只是文件被在飞票占着 ⇒ 本票写 `idle:` 等那张合入后续派，⛔ 拆新票；本票已过大（边界 2）才拆。（实测两张这形状的票，实施回报都给过「等那张合入后续派本票」这个选项。）
- 四查都不中才立新票；票面写一行 `- 立票理由：四查未中（①…②…③…④…）`（例外写 `- 立票理由：例外（<类别>：…）`），让下一次收敛能复核。
- 例外：隐私 / 数据安全 / 安全红线可立即另立并插队；`<类别>` 只认这三个。

**三条边界**（对抗审查后定）：
1. ⛔ 往**在飞 / 已开树**的票里塞活：它会和该票的实施并发写同一棵树，或逼质量链做实施。只往**未开树**的票里并。
2. ⛔ 合并后撑破体量：合并目标预估超过约 25 个文件 / 1000 行就不并，宁可分票（实测 28 文件、diff 2046 行的票实施 36 分钟、质量链两轮）。
3. 有些新票是**因为目标文件被在飞票占着才另立**、又不属于本票 delivers（属于的走 ④）。这类票并进「同文件**且同不变量**的下一张未开票」比另立好；没有这样的票才另立。⛔ 只看同文件：实测一张「开库判降级就删库重建」的票，同文件的未开票有三张、都不是这条不变量，照「同文件」会被错并。

**机器怎么管**（`schedule.cjs`）：带 `inserted:`、未勾、还没开工（无 `impl:` / `qc:` / `qc-metrics:` / `cm:` 记账；`batch:` / `with:` 不算开工）的票缺这一行、或四个圈号没写全、或例外类别不在三类之内、或 `missed` 给出的并进候选没在理由里逐张点名 ⇒ `missed` 把它列在 `🚫 立票守卫` 下、**不算够格**，`worktree.cjs open` 拒开，stop-guard 把它当成当回合的活催。`missed` 同时给出每张的并进候选——① 共写**少见**文件的、② 同前置且共写**非汇聚**文件的未开树票——**写理由前先看那一行**，理由里逐张写它为什么不并（机器查票号在不在）；没给候选不等于 ①② 不中（同不变量 / 前改后才好改不一定体现在文件上）。汇聚文件 = 生成物 + tickets.md `## 汇聚文件` 段登记的（写法同 `## 生成物`，目录以 `/` 结尾）+ 被超过 6 张未开树票声明的；项目的台账 / 命令总表若声明它的票不多，频次认不出，要登记进那一段，否则会被当成少见文件、把无关的票列成 ① 候选。启用前就在台账里的旧插票用 `intake-guard-since: T<n>` 豁免（tickets.md 任一行，建议放 `## 冻结面` 段首），票号 < n 的不查。
⚠️ 机器只查形状，不查真伪：写一行「四查未中（①无 ②无 ③无 ④无）」能过门。真伪靠每次批次收口后的周期收敛审查复核。

## 先核这张票该不该存在（依据来自代码自陈时**必做**）

新票的立票依据是**代码里的自陈欠账**（头注/`TODO`/「已知问题」/「待修」这类字样）时，
⛔ **不许照着它立票**，先回 `spec.md ## Decisions` 与 `alignment.md` 的决策台账查一遍：
**这条欠账是不是已经被裁定「不做」了。**

判据：欠账是代码作者当时的判断，决策台账是开发者后来的裁定，**后者晚于且高于前者**，
而代码里那行字不会因为裁定而自己消失。

实测（2026-08-31 T44）：某票依据一处头注自陈的「已知欠账」立起来，而同源决策
（`Decisions` 15/16）**前一天已被撤销**，撤销理由恰恰是「这是『不相信后端返回』的教科书形态」。
实施代理 + 三评审 + 主 session 全程没有一个环节把两者对上，一路做到 commit 前才因为
**恰好命中安全红线**触发 `AskUserQuestion`、被开发者当场推翻。
⇒ 那次拦住它靠的是运气：同样的漏子若不带安全含义，会直接落地，而机器门四条断言全过。

⚠️ 反过来也要核：台账里**没有**这条欠账，不等于它可以立票——它可能属于
`spec.md ## Out of scope`，那走下面「必须停下问」。

## 同一段查出多条：耦合才并成一张

同一张票的**同一段**（实施回报，或质量链回报）一次报出多条、且都已决定另立票的，立票前先两两比 `Touches`（质量链就地修掉的机械型不立票，不在此列，见 `quality-chain.md`）：

- **耦合（同一不变量，或前一条改完后一条才好改）→ 并成一张**，`delivers:` 逐条列出。分开立只是多付几遍每票固定开销（实测约 18 分钟子代理 + 10 分钟段间等待与合入）。⛔ 只经汇聚文件（台账 / 生成表 / 不变量文档 / 命令总表这类多张票都写的文件）相交**不算耦合**——非追加型的同文件不同区段由 stage-3 `shares:` 放行，追加型只排队，与上面四查 ② 同一口径。
- **不耦合 → 分开立**（含只经汇聚文件相交的）。并了会丢并行，而且票越大越慢（实测单票耗时中位随改动量从 18 分钟涨到 56 分钟）。
- 不同票、不同段查出的不在本节两两比之列——它们各自走上面「立票前四查」：①② 本来就是跨来源并（并进的是别处立的未开树票），只是目标必须**未开树**（边界 1）。

实测（2026-09-21-mthu）：有同源兄弟的插票 45 张 / 18 组，写集相交的 11 组（旧口径，含只经公共文件相交）；按旧条能少立约 20 张，按耦合口径会更少。收益有限，别为了凑并去放宽 `Touches`。

## 要不要先问开发者：按新票是否改变**本期交付面**分

- **不问，直接插**：新票只是让某张已有票的 `delivers` 真正成立（清单枚举不全、刚交付的工具/门禁有缺陷、票面事实写错导致落点要拆、**真机 / 收口测试跑出的崩点**）。插完**当回合就派**，在下一次汇报里点名，一句话说清「为什么它属于既定范围」。⛔ 「汇报崩点 → 结束回合 → 下一轮立票」不是一种流程：实测三次这样收尾，分别停了 36 / 212 / 57 分钟。
- **必须停下问**（走 `revision-protocol.md` 的 L2）：新票带来 spec `## Out of scope` 之外的行为、推翻已记录决策、或要动一条已声明为本期不碰的路径。

## 插完立刻回写 tickets.md

照 stage-2 的完整票面规格写（`- [ ] T<n> <标题>` + `delivers:` + `Blocked by:` + `Touches:` + `AC:`），**再加两条缩进子项 `- inserted: <日期>`**（取票优先级，见「排进执行序列」）**与 `- 立票理由：…`**（见「立票前四查」；缺它这张票开不了树）。票面上需要开发者先拍板的事项写成待问，开发者答复后只按他原话覆盖的范围改（`stage-3.md` 完成条件第一条）。它是下一次 /clear 之后唯一的真相源。

⛔ **必须插在票列表区里、第一张未勾票之前**（`## 票` 段内；没有未勾票就放在该段最后一张票之后、下一个 `## ` 标题之前）。放在这里是为了让它留在票列表区、被脚本与机器门看见；**优先级靠 `inserted:` 子项表达**（见下面「排进执行序列」）。**不要追加到文件末尾、也不要追加到「文件里最后一张票」之后**——那张票可能已经在 `## 已知障碍` / `## 收口记录` 段下（实测 41/96 张票就这样落进了那两段）。机器门对 `## 待真机验证` 段有专门断言：段内出现任何 `- [ ] T<n>` 一律 fail，而它给的修法是「改写成非复选框条目」——照做等于把这张真票从全部完成判定里删掉（它从此不参与「无未勾票」「qc:done」「票↔commit 配对」「写集」四条断言）。

**`Touches` 照 stage-2 的收窄条款写**（`stages/stage-2.md` 的「新增测试 → 测试文件逐个写到文件名」「窄到『读它就能看出这票在改什么』」两条）。插票时最常犯的两种，都会让这张票和一大片票判成相交、名额空着也开不出去：
- **已存在的测试目录 / docs 目录写成整目录**（`src/main/<域>/__tests__/`、`docs/invariants/`）→ 写到文件。新测试文件名由你定，定了写进来，实施按这个名字建；只有**本票新建**的目录才写目录本身。
- **声明源码根整体**（`src/main/`、`src/preload/` 这类整棵子树）→ 列出要改的文件或下一级目录。

实测（2026-09-21-mthu）：98 张插票里 50 张把已存在的测试目录写成了整目录；一张插票写了 `docs/invariants/`，和三张各改其中一个文件的在飞票判成相交，收窄到文件后才够格。`gate-stage-2.cjs` 会对未勾插票里第一种（已存在的 `__tests__/` `test/` `tests/` 目录与 `docs/` 下的子目录）打 `⚠`，不拦。

## 把 stage-2 那道门再跑一遍

⚠️ **新票不会再经过 stage-2 的机器门**（`gate-stage-2.cjs` 只在 stage-2 写 signal 时跑一次）。别手工复核格式——把门跑一遍：

```sh
node <FD>/scripts/gate-stage-2.cjs --flow-dir <FR> && echo "格式 OK"
```

它是纯读脚本，对已勾票与未勾票一视同仁，stage-3 中途跑不会因为「flow 已经开跑」误报。**exit 0 才算插票完成。**

最容易漏、且漏了**不报错**的是两条：`Touches:` 要写成该票行的**缩进**子项、且**有值**——顶格或空值的表现不是报缺字段，而是断言⑥ 对该票**整个跳过**（gate 只打一行 `⚠`），越界保护静默消失。

## 排进执行序列

**新票按 `Touches` 与在飞票的相交情况准入**，和原有票同一套判据（stage-3 第 1 步）；**名额与写集允许就当回合开，优先于已有够格票**。理由：发现它的 session 上下文还在，落到后续 session 就得从零读起。**优先级靠一个缩进子项表达：`- inserted: <日期>`**——`schedule.cjs missed` 把带它的票排在最前（其后才是下游依赖链长降序、文件顺序），/clear 重入算得出同一结果。⛔ 别省：取票顺序的第二级是下游链长，插的票多半是链尾，没有这个标记就会排到所有链上票之后（实测 40 票模拟，名额满时它的等待从均值 0.11 个单票工时涨到 0.69，最坏 4.6）。

**排定后立刻在该票行写 `lane: R<n>`**（一票一树模式下开树时写 `batch: B<k>` + `with: <在飞票>`）——分组只存在于这个字段里，漏写一张，`schedule.cjs` 就整体退回「连通分量」分组，跨车道相交校验与跨车道票点名不再触发，**而输出不会告诉你它降级了**。
