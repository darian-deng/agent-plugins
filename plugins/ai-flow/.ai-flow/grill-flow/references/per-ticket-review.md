# 一票交付契约（stage-3 · 实施段）

> **读者是执行一票的实施子代理**；主 session 按本文件拼 dispatch prompt。调度侧的事（算批次、开收 worktree、回合、记账、拍板）在 `stages/stage-3.md`，本文件不复述。
>
> **一票走两段，你是第一段。** 你的交付物 = **改动留在工作树、不提交** + 一份精简回报。第二段（三评审 → 裁 findings → 客观地板 → commit）由主 session 另派一个**全新上下文**的子代理完成，契约在 `quality-chain.md`。注释清理在那之后由**主 session** 另派（commit 之后、`close` 之前）。
>
> ⛔ **你不 commit、不派评审、不调 `comment` skill、不跑整仓测试。** 走完实现就交班——这是刻意的：实测那一段跑在你这个已经堆到 40 万 token 的上下文里，会吃掉整张票 43% 的成本，而它在一个新开的上下文里做同样的事起步只付 17K。
>
> **不属于你**：`AskUserQuestion`（人在环只在主 session 那侧）、记账（tickets.md 的 `qc:done`/`[x]`/`rm:pending`、candidates.md）、开收 worktree。**子代理不写 `docs/grill-flows/**`**——在 worktree 里提交那里的文件会让后续所有归并被 git 阻断。

## 最重要的一条：路径与 cwd

**每次 Bash 调用之间 cwd 可能被重置回主仓，不要依赖 `cd` 的持久性。** 本票的一切命令都要显式指向自己的 worktree（下称 `<WT>`，由 prompt 里的简报命令 `schedule.cjs … brief T<n> impl` 给出绝对路径）：

- git：`git -C <WT> …`（**所有** `git diff` / `status` / `add` / `commit` / `log`）
- 包管理与测试：`npm --prefix <WT> …`，或单条命令内自带 `cd <WT> && …`
- Write / Edit 的 `file_path`：一律 `<WT>/…` 绝对路径

**`<WT>` 是那棵工作树里的项目根**，和你那张票 `Touches` 里的路径同一个基准——`<WT>/` 直接拼 `Touches` 上的路径就是对的。monorepo 里锚点是子项目时，工作树根在项目根之上还有几层，主 session 会把它作为 `<WT_ROOT>` 一并给出；只有改**锚点之外**的包（`Touches` 里写成仓库根相对的那些，如 `packages/net/…`）才用 `<WT_ROOT>/` 拼。拼错的症状是凭空建出一层同名目录（`<WT_ROOT>/src/…`）而机器门不报——**没拿到这两个路径就别猜，回报里问**。

**这不是风格问题**。漏掉 `-C <WT>` 的 `git diff` 会在主仓求值，看到的是空的或别票的记账改动——于是三评审审空 diff、`comment` skill 的范围算错，整条质量链静默空转而不报错。写文件时漏掉绝对路径更糟：引擎那道「cwd 漂移时禁相对路径」的守卫在 cwd **恰好是主仓**时不触发，于是改动落进主树，本票 commit 缺内容。

## 有疑问先查给你的文档

你手上没有前面两个阶段的对话，只有它们落下来的文件——**而「这个当时定过吗」的答案通常是「定过」**。所以在把任何事情写进「需主 session 拍板」之前，先查：

- **做到什么程度算完 / 为什么是这个方案 / 某写法是不是已经否掉了** → 派发给你的 spec 相关段（`## Decisions` / `## 方案审查` / `## User Stories`）
- **测什么、在哪一层测** → spec 的 `## Testing Decisions`（seam 是 stage-2 定死的，别自己另选一层）
- **本票的预期行为、边界** → 该票的 `AC:`
- **本票该碰哪些文件** → 该票的 `Touches`（新建的测试文件照这里写的文件名建）
- **既有模式/约定** → 给你的 ADR 路径；前置票的 commit（`git show <sha>`）
- **术语** → 派发 prompt 内联的票面与 spec 切段里的用法。⛔ **不要索要 `tickets.md` 路径**（那是一份很大的文件，读进来之后每一轮都重新计费）；那里面确实有你要的东西时，主 session 会切好给你。

查到了就照做。**只有查完确实没有依据，才写进回报**——每一条不必要的上报都会让主 session 停下来问开发者一件他早就定过的事。

## 核心：改动留工作树，commit 归第二段

实现的改动**先留工作树不提交**（`git -C <WT> diff` 看得到）。第二段的三评审与客观地板审的就是这份未提交改动，最后由它一次性提交为本票唯一那笔 commit。那笔 commit 因此是「本票质量已跑完」的锚——主 session 的重入判据据它判相位。

**为什么不让你顺手提交**：三个评审读的是 `git diff HEAD`。改动一旦提交，那个 diff 就变空，三个评审会各自对着空 diff 写出一份「没发现问题」——而这不报任何错误，「真的没发现」和「读到空 diff」长得一模一样。实测发生过一次。

## 派发时带什么（机械部分交给简报命令，prompt 只写你判断过的）

🔴 **prompt 第一段固定是简报命令**：`node <FD>/scripts/schedule.cjs --flow-dir <FR> brief T<n> impl`（`<FD>` / `<FR>` 给绝对路径）。它现切现给 `<WT>` / `<WT_ROOT>` / 回报落盘路径（自动取下一轮 `<k>`）/ 票面 / 交接段 `### 派发纪律` 原文，子代理开工先跑。⛔ **这些别再抄进 prompt**——实测一个 42 分钟的 session 派了 25 次，prompt 合计 6.5 万字符，其中光抄派发纪律就 2.6 万，还是有损抄写（原文 9.3K，prompt 里平均剩 1.5K、17 份出现 8 种版本）。下面列的其余各条（spec 相关段、前置票结论 + sha、ADR 路径、点名豁免）才是 prompt 的正文。

- **代理类型：`subagent_type: "ai-flow:grill-impl"`**（opus，effort 跟随开发者配置；定义里禁掉了 `Agent` 工具）。⛔ 别用 `general-purpose` + `model: "opus"` 代替：模型只该在代理定义里写一处，而且那样拿回了派孙代理的工具。⛔ 也别同时传 `model` 参数，它会覆盖定义文件头里的模型。
- **`description` 以 `T<n>·实施` 开头**（续做轮写 `T<n>·续做`）：代理面板第一行的「在跑 N 张票」和 Stop 守卫的「名额空几个」都靠这个前缀数票号；漏写会让守卫少数一张、催你多开一张而超过上限。
- **spec 只切相关段**，不塞整份 spec.md
- **files 用符号锚点**（`@ 导出名`）让子代理自己按需 Read，不预读整文件、不在 prompt 里粘代码块
- **前置 ticket 的改动只给 commit SHA 指针**（"自己 `git show <sha>` 看、在此基础上改、勿覆盖"）。`git show` 走共享 object DB，在任何 worktree 里都能读
- **tracer-bullet 竖切 + 该票的 decisions/AC 整段**必带（护栏，必须全）
- 相关 ADR 只给**路径**（≤5 条）
- `<WT>`、`Touches`、**回报全文的落盘路径**（`<FR>/state/reports/T<n>.impl-<k>.md`，`<k>` 每轮唯一、⛔ 不许覆盖前一轮——质量链要读全部轮次）都由简报给。`<FR>` 必须是主仓里的真实路径，⛔ 不是 worktree 里那份 `.ai-flow` 副本（worktree 拆除时会连同 gitignored 的内容一起静默删掉）。回报形状见下面「固定顺序」第 2 步
- ⛔ **`<FD>` 的绝对路径每次都从注入 context 顶部 `[ai-flow:paths]` 的 `flow_def:` 行现取，不要从上文里抄。** 它带插件版本号（`…/ai-flow/<版本>/.ai-flow/<flow>`），插件一升级就变；跨越 0.69.0 迁移或跨插件升级恢复的 session，上文里那个是失效路径。实测过一次：resume 之后主 session 照旧从上文拼路径，三个质量链子代理全部拿到已被删除的 `references/` 路径，一个绕到自己 worktree 里那份陈旧副本，一个跑了 `find /` 全盘扫描。（引擎现在会拦下这种 `Read` 并点名正确路径，但那是兜底，不是让你少写这一步的理由。）
- ⛔ **票面不内联、也不给 tickets.md 的路径**——简报里带着（与 `ticket T<n>` 子命令同一份输出），子代理自己跑，拿到的是票行 + 全部缩进子项（`delivers` / `Blocked by` / `Touches` / `AC` / 你补过的 `rest:` 等）。理由两条：① 原先整段内联，同一段票面每票进主 session 上下文三次（你读一次 + 实施、质量链 prompt 各抄一次）；② 你在实施之后常改票面（补 `Touches`、改 AC、写 `rest:`），命令每次取的都是最新版，不会拿到过期快照。给 tickets.md 路径仍然禁止：实测子代理拿到路径就整篇读（**14 次**），而读进去之后它在此后每一轮都被重新计费。**你自己仍要读一次票面**（写派发要点、复核 AC 都要用），省的是两次抄写。
- **`Blocked by` 的前置票**：给票号 + 一句结论 + 它那笔 commit 的 sha（"自己 `git show <sha>` 看"），不要让子代理去 tickets.md 里翻。
- ⛔ **不要给 `scripts/gate-stage-3.cjs` 的路径**（≈10K token，实测被整篇读了 15 次）。本文件末尾的「机器门规格」四条就是子代理需要的全部；真撞门报错时主 session 会把那一条报错文案原样转给它。
- ⛔ **不带 `comment` skill**——注释清理由主 session 在该票 commit 之后、`close` 之前另派（见 `quality-chain.md` 第 3 步）。在这里跑等于让它跑在最胖的上下文里，而且它的判据是「陌生读者冷读」，你读过这些改动，判不了。
- 🔴 **注释写时纪律不再内联**：整块已写进 `agents/grill-impl.md` 正文（子代理的系统提示，每次派发确定送达、不经主 session 转写）。⛔ **别再抄进 dispatch prompt、也别改写一份精简版**——实测「原样内联」的规定下，27 份实施 prompt 只有 18 份带了它（有一个 session 8 张票全漏），带了的与原文相似度也只有 0.23–0.34；漏带的代价已实测：11 张票新写 462 行生产注释、事后清理砍掉 273 行（59%）。本票若确有豁免（例：某条取舍注释必须保留），在 prompt 里**点名写明**。

## 固定顺序（实施段只有这两步）

1. **实施**（`ai-flow:grill-impl`：opus）：TDD 只在 stage-2 约定的 seam 上测 → 实现 → 改动留工作树。
   - ⛔ **不跑 `/simplify`**——这个环节已整步删除（开发者 2026-09-03 拍板），它那四类由第二段的 Standards 轴接管。
   - **先跑一次最小自证再交班**：typecheck + 本票测试。⛔ 只回摘要不贴整段日志（`2>&1 | tail -40`），跑绿的那次尤其只需要一行结论——实测单个代理内跑过 41 次 typecheck，每一次的整段输出此后每一轮都在重新计费，而除了最后一次全部已经作废。完整地板（含假绿检测、枚举负空间、影响范围测试）归第二段，你不重复跑。
   - ⛔ **不要跑整仓全量测试，也不要把任何命令丢后台。** 你没有「挂起」这个状态：整仓全量（本仓网页端 ≈2 万条用例）超出前台单条命令的超时上限，唯一出路是 `run_in_background`，而丢后台之后你无事可做、只能结束本轮——**结束本轮 = 你被终止**。宿主随即给主 session 发一条 `completed`，正文是你最后那句「在等 X」，读起来像「还在跑」。实测这个形态发生过 **8 次以上**，最长一次空转 **1 小时 07 分**。整仓全量回归属于主 session 的批次收口。
   - **近上限 / 发现本票比预期大**：别硬撑到被截断。`git -C <WT> commit` 已完成部分（subject 含 `T<n>` 并标 `[partial]`，如 `feat(T3): … [partial]`——票号一开始就要在）+ 回报里写「剩余工作」清单（差哪些、做到哪、从哪继续）+ 报「完成但有顾虑」。主 session 会把它落成票面 `rest:` 字段（/clear 之后靠它续跑），再按它**续派实施代理**——不是让质量链代理捎带做，理由见 `quality-chain.md` 形态乙——最后由质量链代理 `--amend` 折回那笔、去掉标记，保住一票一 commit。这是本段唯一允许 commit 的情形。
   - **你自己就是那个续做的实施代理时**（prompt 带着剩余清单——来自票面 `rest:` 字段——分支上已有一笔 `[partial]`）：⛔ **不要再 commit**，改动照常留工作树。那笔已经在了，第二笔会让机器门的票↔commit 配对只认领其中一笔、另一笔的改动整个逃过 `Touches` 核对。你也近上限就报「未完成」+ 更新剩余清单，主 session 再续派一轮——工作树的改动跨轮累积，最后一次性被 `--amend` 折进去。

2. **回报分两份：全文写文件，最终消息只回首屏。**
   - **为什么**：你的最终消息会原样进主 session 的上下文，此后它每一轮都重新计费。实测一个 session 里 28 份回报约 19.5 万字符，是主 session 上下文里最大的一类（约 23%），而主 session 真正要据此动作的只占三成左右；上下文到 61% 就触发收尾、等开发者 `/clear`，一次空档 4 小时。
   - **全文**：用 Write 写到简报给的那个绝对路径（拿不到就在首屏里问，⛔ 别自己拼 `<FR>`），内容按下面各条写全——它是质量链代理读「取舍」的来源，也是 `/clear` 之后找回回报的第一落点。
   - **首屏（最终消息）**：划界按「**主 session 要据此动作、或要转告开发者**」，⛔ 不按长度——该进首屏的一条都不许压成一句。依次是：首行（格式见下，不变）；状态（受阻时第一句写清卡在哪一步 / 工作树里有什么 / 从哪继续）；1–2 行「做了什么」（主 session 给开发者的进度汇报用它）；读到的基准 sha 一行；AC 逐条一行；以及下面**标了「首屏」**的各条全文；最后一行是全文路径。其余（改了哪些文件逐条做了什么、`git status` 原样输出、取舍全文、新术语、沉淀候选）只进全文。
   - 全文的内容：状态（**完成 / 完成但有顾虑 / 受阻 / 需补充信息——只有这四种**）+ 改了哪些文件做了什么 + 本票引入的新术语/模式 + 沉淀候选（⛔ 为绕开某条门禁 / 文档规定而采用的手法**别写成沉淀候选**，写进下面「取舍与为什么不选 X」并点名被哪一句挡住——写成候选会在 stage-5 被沉淀成规则）+ 需主 session 落账或拍板的项（**首屏**）：
   - **首行必须是** `impl-done: <N> 个文件已改，未提交；AC 已交 <编号列表|全部> / 未交 <编号列表|无>`，或 `未完成，原因：<一句>`，或（截断自保护时）`commit: <sha> [partial]`。主 session 靠它判相位，缺了就只能再派一轮。它随后会用 `git -C <WT> status --porcelain` 非空来复核这一行。
     - **AC 那一段逐条对着票面 `AC:` 点名**，写成 `AC 已交 1,2,5 / 未交 3,4`；一条不落时才写 `全部`。⛔ **不许笼统写「全部」了事，除非你真的逐条核过**——每一条 AC 都指得出对应的实现改动和（按 stage-2 定的 seam 写的）测试。
     - **编号要对得上票面 `AC<n>:` 的编号。** 你写进 `已交 1,2,5 / 未交 3,4` 的每个数字，都是票面那条 `AC<n>:` 里的 n，⛔ 不是你自己按实现顺序重排的序号。对不上时主 session 没法把 `未交` 那几条落成 `rest:` 续派（键都对不上），只能整票退回重核。
     - ⛔ **写 `=> rm` 的那些不许自己跑、也不许声称已交。** 票面 AC 只有两种形状（stage-2 切票时定死的）：

       ```
       AC<n>: <一句话> => `<命令>` => `<期望输出的字面片段>`
       AC<n>: <一句话> => rm
       ```

       第二种你跑不了——契约禁子代理起 Electron、禁跑长命令。它的交付**不是「我验过了」，而是「在回报里点名了它」**：真正的登记（`## 待真机验证` 段 + 票行上的三态）归主 session，在你交班之后的第 5 步做（见本文件开头「不属于你」）。⛔ 所以**别去票面上核有没有 `rm:pending`**——你跑的时候它必然还不在。你要做的是在回报下面那条「需真机验证」里**点名它是哪几条 AC**，让主 session 登得全。实际验证发生在别处——stage-4 环节 C 由开发者做，那是全流程唯一的真机验证落点。⛔ 把 `=> rm` 的条目算进 `已交` 是瞒报的一种，下一条同样管它。
     - 🔴 **欠交不是罪，瞒报才是。** 欠交会被接住：主 session 把 `未交` 那几条落成票面 `rest:` 字段，再据此续派一轮实施代理。瞒报（少做了几条却写 `全部`）则让欠的那几条**静默消失**——首行照写、`git status --porcelain` 非空，两条机械判据**全绿**，主 session 没有任何抓手能发现。实测：某张 **9 条 AC** 的票，子代理只交了 **3 条**，机械判据全过，欠交到下游才暴露。
     - **首屏**：动手前基线跑出来已经通过的 AC，写一行 `AC 空过：AC<n>（基线输出 <原样片段>）`（判法见 `agents/grill-impl.md`「改任何文件之前」那条）。它不进首行、不算未交；主 session 收到后在质量链之前把那条 AC 改成先红的写法（命令或期望片段收窄到本票新加的东西），⛔ 不能拿空过的那条判「已交」。
   - ⛔ **「我在等 X」不是一种状态。** 测试还在跑、命令没回——那些时候你没有可交付的东西，返回等于向主 session 谎报完成（宿主会照发 `completed`）。两条出路：① 阻塞等到底；② 确实等不到（工具挂死、超时）→ 状态写**受阻**，正文第一句写清「卡在哪一步 / 工作树里现在有什么 / 从哪继续」，让主 session 能续派而不是重做。
   - **回报之前重跑一次 `git -C <WT> status --porcelain`** 并把结果写进回报——第二段要靠它确认接到的是什么。
   - **实现里的取舍与「为什么不选 X」写进回报全文**（其中「被哪条文档 / 门禁挡住所以绕了」的那几条同时进**首屏**，主 session 要据此记 `doc-suspects.md`）：第二段的代理没写过这段代码，评审 findings 里凡是问「为什么这么做」的，它查不到依据就只能上报给主 session。你这里多写两句，能省掉一次往返。
   - **需真机验证**（**首屏**）——判据是「机器地板验不了的」：触发原生 / 主进程运行时、鉴权登录态流转、设备 I/O、跨端真机行为等。**漏报的代价是静默的**：主 session 据此打 `rm:pending`，而 stage-4 的收口**只认该段登记过的票**（没登记 = 对收口方不存在），于是全流程唯一的真机验证落点被整段跳过，且不报错。宁可多报一条让开发者驳掉。
   - **越出 `Touches` 的文件及理由、截断自保护时的「剩余工作」清单**（**首屏**）：主 session 要据前者补声明或拆票、据后者落票面 `rest:`。

## 归并前自适配（并行票）→ 不归你

主 session 回合失败把票退回来时，派的是**质量链代理**（它手上有地板与 `--amend` 两步，你没有）。全部做法在 `quality-chain.md` 的同名节，本文件不复述——复述必漂。

## 安全红线五类（定义，余处引用此节）

**鉴权绕过 / 注入 / 密钥·敏感数据外泄 / 越权 / RCE**。

命中这五类之一 → 报给主 session 停下问开发者。纯防御性加固、不涉及可利用路径的当常规 bug 内联修，不必上报。correctness 轴要主动去发现这五类；「何时上报」以本节为准。

## 领域事实：预期的中间不可编译态

本 flow 的切片策略**刻意**会产出中间不可编译态——wide-refactor 走 expand → 分批迁移 → contract，本票先动一处、consumer 要等后续某票才补齐。所以你那次最小自证的 typecheck 红了、而红的原因指向「还没到的那张票」时，**那不是你的缺陷**，写进回报即可，别去把别的票的活提前做掉。

⛔ **撞 pre-commit hook 的处置不在你这里**（本段不 commit）——见 `quality-chain.md` 第 5 步。

## 机器门规格（写成什么格式才过得去）

以下四条不合就 fail-closed 拦下（提交由第二段做，但你的实现要落在这四条之内）。完整七条断言与各自理由在 `scripts/gate-stage-3.cjs` 的头部注释里——⛔ **不要为了「先了解一下」去整篇读那个脚本**（≈10K token，读进来之后每一轮都在重新计费）；真撞门报错时主 session 会把那一条报错文案原样转过来。

- commit subject **首行**含票号、**且只含本票号**（提及别的票写进 body——门只读首行；首行出现多个票号会让票↔commit 的配对不唯一，两票都会被误报越界）
- 历史**线性**：区间内不得有 merge commit
- 本票实际改的文件 ⊆ 声明的 `Touches`（记账区不计）
- 本票那笔 commit 的 diff **不能是空的**（空提交会被当成「没有交付物」拦下）
