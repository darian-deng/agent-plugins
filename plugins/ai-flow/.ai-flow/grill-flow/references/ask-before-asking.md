# 先查文档，再问开发者

> **触发**：任何「要不要停下来问开发者」的念头。它是模型自省型的触发——你想问的那一刻就是读这份的那一刻。
> 子代理那侧的同一条纪律在 `per-ticket-review.md` 的同名节。

到了本 stage，前面两步已经把决策落成了文件。**执行越往后，「这个当时定过吗」的答案越是「定过」**——而你手上没有那段对话，只有文件。所以：**任何「要不要停下来问开发者」的念头，先当成一次查证任务**。

| 疑问 | 查这里 |
|---|---|
| 做到什么程度算完 / 要不要做 / 是不是推迟了 | `alignment.md` 的 `## 需求`、`## 不在范围内`、`## 暂缓` |
| 为什么是 A 不是 B / 某方案是不是已否掉 | `alignment.md` 的 `## 关键决策`；`spec.md` 的 `## Decisions`、`## 方案审查` |
| 这个词在本项目里指什么 | `alignment.md` 的 `## 术语表` |
| 测什么、在哪一层测 | `spec.md` 的 `## Testing Decisions` |
| 预期行为是什么 | `spec.md` 的 `## User Stories`；该票的 `AC:` |
| 跨端 / 跨仓怎么约定的 | `spec.md` 的 `## 跨端/跨仓行为契约` |
| 谁先做 / 能不能一起做 / 该碰哪些文件 | `tickets.md` 的 `Blocked by`、`Touches` |

- **查到了 → 照做，不问。** 把已定的事再问一遍，等于让开发者重做一次已经做过的功课。
- **查不到 → 才问**；拿到答案**立即写回上表对应的那个文件**。`AskUserQuestion` 的结论不落盘，下一次 /clear 之后就会被重新问一遍。
- **查到的结论与你此刻的判断冲突 → 不自行推翻**，走 `revision-protocol.md`（L1/L2 必须停下）。

同一条纪律对子代理同样成立，它那侧的版本在 `per-ticket-review.md`。

## 查完仍要问 → 先派对抗审查，⛔ 不许直接问

上面那一步过了（文档里确实没有），**也还不能直接 `AskUserQuestion`**。⛔ **不许跳到第三步。**

**三步，写死**：

1. **自己先形成一个带依据的推荐。** ⛔ 不许把选项摊开就交出去——**没有推荐的对抗审查没有攻击面**。
2. **派一个 fresh-context 子代理专门攻它**：给它推荐、依据、以及你否掉的替代方案，要求它**尽力推翻**并**自己复跑取证**。
   ✅ **允许它回「攻不动」，但必须交代怎么攻的**：写清**试过哪几个攻击角度**、**每个角度用什么命令 / 读了哪个文件哪一行取证**、**为什么没攻下来**。⛔ 禁的只是空洞的「基本同意，补充几点」——那种回报不含信息；**零结果本身合法**（`stages/stage-2.md` 的对抗性方案审查早就这么定：「即使无阻塞项也必须写该段」，记「已审查，无阻塞项」）。
   🔴 ⛔ **不许为了交差造反驳。** 「必须找出不同意见」这条指令会把子代理变成反驳生成器，而它造出来的反驳会被当成战果采纳——一个 99 分的方案就是这样被「优化」成 85 分的。⇒ 一份诚实的「攻不动 + 我试过这五条路」比一条硬挤出来的 finding 有价值得多。
   🔴 **依据不是口味，是公开实证**：没有外部信号时让模型自查自纠，性能不是持平而是**下降**（ICLR 2024《Large Language Models Cannot Self-Correct Reasoning Yet》，瓶颈名为 verification bottleneck——模型判得出一个回答得不得体，判不出自己的推理哪一步错）；多代理辩论的典型失败形态是**说服力压倒正确性**（《Talk Isn't Always Cheap》）；谄媚会在代理之间**传播**、互相强化偏差（《Too Polite to Disagree》）。⇒ **「几个 AI 都同意」不构成证据**：有案例是 80 多个代理一致背书一个根本不存在的漏洞，被一条测试一击杀死。
   **它的 finding 要不要合并，按下面三条判**：
   1. **每条 finding 必须带可复跑的取证**：一条命令 + 它的输出，或 `文件:行号`。⛔ **拿不出取证的一律不合并**，哪怕听起来很有道理——「听起来有道理」正是说服力压倒正确性的入口。带取证把推荐整条推翻的，就按它的结论走。
   2. **举证责任在挑战方；平局保留在位方**：双方都只有论证、没有取证时，**默认保留原方案**。⚠️ 没有这条默认值，每一轮只要挤得出一条「算是站得住一半」的意见，方案就被改一次，而且是**单向**的——那就是 99 分磨成 85 分的机理，每一步都看起来像在优化。
   3. **裁决方必须自己跑一条**：主 session 采纳任何一条 finding 之前，**至少亲手复跑它给的一条取证命令**。⛔ 不许只读论证就采纳——那裁决的是文采，不是事实。
3. **只有几个来回都收敛不了才 `AskUserQuestion`**，且要写清**攻不下来的那一点**是什么。

⚠️ **判据是「这件事必须开发者决策吗」，不是「主 session 有多不确定」。** 「必须开发者决策」那几类由本 flow 自己的 `alignment.md` 定义（典型是「改变用户可见功能的取舍 / 越出已结账的清单 / 跨仓代价显著上升 / 与已拍死的结论冲突」这一类），开工时按本 flow 的实际标题定位。
⚠️ **反向也成立**：属于那几类的 ⛔ **不要先审一轮再问**——那只是延后开发者该拍的板，还多烧一轮。
⚠️ **「架构上不确定」不是停下来的理由**：判据要可运行（拿一条真实缺陷去试跑）。试跑仍分不出高下时取「错得更明显」的那个，把假设与后果写进产物，继续往前走——⛔ 不要把一次可逆的技术选择包装成需要开发者拍板的问题。

🔴 **派对抗审查时的三条实测纪律**（漏了会让整轮结论作废）：

- **钉死 sha**，或在 prompt 里写明「回报里必须写出你实际读到的 sha」。**若主 session 正在往同一分支合票，基准会在它跑的过程中前进而它无从察觉**——实测踩过一次，害它第一轮结论整体失效。
- **它给的「归属 / 落点」必须是真实存在的东西**。实测：某轮子代理给了四个**不存在的票名**当归属，那等于仍然无主。⇒ 归属只能由主 session 立票兑现。
- **回报必须给得出「枚举面」**：凡对抗审查，回报要能回答三件事——**你枚举了什么面、枚举了多少个、逐条结论是什么**。答不出枚举面的是意见交换，⛔ **不该有推翻权**。🔴 正面样本就在本仓：`assembly-review.md` 记载的安全专项，把 base 与 HEAD 的 **429 / 392 个端点**（「方法 + URL」去重后）逐对比对了鉴权轨声明，**57 条字面差异全部核实归因**。那是枚举 + 逐条核实，所以它的结论站得住；它的价值不随票数走，正是因为它有一个**可数的面**。

⚠️ **这条规则本身要落进本 flow 的产物**（决策台账 + 交接段），⛔ 不能只活在这份定义里。落点已经有了：`handoff.md` 的入场表第 ⑧ 格就是「主 session 自己的行为纪律」，它和本节是同一批补的（补之前那张表只有七问、没有任何一格指向主 session 的行为纪律，所以没有机制要求交接段写它——那就是它被漏掉的机理）。**⛔ 交接段里要就地写全，不给指针**——指针会被跳过，而这类错误发生时不报任何错。

🔴 **实测它会被违反，而且是在「文档三处都写了」的情况下**：某次 flow 的 stage-3，规则同时写在 `alignment.md`、`spec.md ## Decisions` 与 `tickets.md` 交接段三处且互相一致，一个新 session 仍然连着两次直接 `AskUserQuestion`。**根因不是记性**——stage 提示词的岔路表把「想停下来问开发者」路由到的是**本文件**，而当时本文件里没有这条规则，那三处产物都是按需读的，走岔路表根本到不了。⇒ 本节就是为此补的。
