# review.md 结构

> **触发**：stage-5 第一次要往 review.md 写东西时；以及任何一次「这条该记进哪一节」的疑问。
> **前提**：每轮处理后必须**立即**写 review.md（各类都即时落盘），**不允许积累在主 session 内存**——/clear 会把内存里那份全部销毁，而 review.md 是 stage-5 唯一的跨 session 状态。

```markdown
# 代码审查

## 审查范围
BASE_SHA_CODE: <SHA>

## 本 flow 改动范围
<环节 C reset **之前** `git diff --name-only <base>..HEAD` 的输出——收尾 `git add -A` 前 scope 核对的唯一依据>

## 集成 & 需求闭环（视角①）

### 已解决
- <问题描述>：<修复方式> — 证据：`<≤5 行片段>`

### 已反驳
- <问题描述>：<反证：≤5 行片段>

## 安全（视角②）

### 已解决（Critical / High）
- <问题描述> [CWE-xxx]：<修复方式> — 证据：`<≤5 行片段>`

### 已反驳
- <问题描述>：<反证：≤5 行片段>

## 待开发者决策（架构级）
- <问题描述>：审查者立场 + 主 session 立场

## 建议（非阻塞）
- <视角① 建议项 / Medium 安全项> — 来源视角 + 一句话理由

## 测试调整记录
- <如有> 改测试的位置 + 理由 + 复核者意见

## 人工 review（环节 C）
- <开发者指出的问题>：AI 改动文件 <file1, file2…> — 回归：通过
- 最终 CR：<跳过（零改动）| 聚焦 CR 结论（视角① / +视角②）>
- squash：<feat commit 概要>

## 结论
<总体评估>
```

⚠️ 「人工 review（环节 C）」节要在 **reset 完成后立即建**（哪怕暂无内容）——它是 `/clear` 落在「reset 已跑、开发者还没提第一个问题」窗口时的恢复标记。
