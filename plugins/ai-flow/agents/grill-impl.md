## 注释纪律（写的时候就守，本票新写的注释适用）

- **默认不写。** 判据是「盖住」：把这条注释盖住，一个称职的**陌生**读者——只看代码 + 命名 + 类型 + 结构 + 测试 + 字符串字面量（文案/日志/错误消息/测试名），并顺着 `import` 用 go-to-definition 跳到定义处——还能不能得到同样的信息？**能 → 不写。** 尤其是替**别处**的代码转述它的内部行为 / rationale / 与别的实现的异同：那归定义处，读者跳过去就知道。
- **只留「本地四类 why」**，每类都必须**同时**满足三条闸门——**本文件*拥有*那段代码** ＋ **代码结构表达不了** ＋ **不知道就会改错**：
  - **缘由**：为什么这么做（本文件的设计 / 业务 rationale）。
  - **否定**：为什么**不**用那个看起来更显然的写法（防好心重构踩回坑）。
  - **约定**：本文件承担的调用契约 / 前置条件 / 非局部约束。
  - **边界**：非显然的边界、外部系统的坑（第三方 API 怪异、协议、历史兼容包袱）。

  ⚠️ 四类是**下界，不是许可证**——别把一条注释硬套成「这也算缘由/边界」来免死。
- **能搬先搬**：「必须非负 / 可能为 null / 只能这几种取值」→ 类型（非空 / 枚举 / branded）；「必须已初始化 / 已排序」→ `assert` / 契约。搬进去代码一变就报错，强过一条无人校验、会腐坏的注释。搬不动的才留最短的一句。
- **硬预算（可数上限，超了必须合并或删）**：每个**函数 / 类 / 方法 / 顶层常量**的**归属注释 ≤3 条、每条 ≤2 行**——**不论物理位置**：头注释 + 函数体内贴该符号的注释**合计**算，「放置就近」不等于绕过预算。**文件顶另许 1 条。**
- **留的要放置就近**：贴在最可能被改错的那一行正上方，别堆函数头 / 文件头。
- **⛔ 不写这几类**：复述 what（`// increment counter` 配 `counter++`）、和下方 `dialog.detail` / `log.info` / 错误消息讲同一件事的、签名复述、注释间互指（「见上面」「同上」）、标榜（「高内聚」「optimised」）、复读 lint / 团队约定已强制的规则、背景小作文、注释掉的代码、分区标题。
- **⛔ 不写「进程指代」**：指向本次流程临时产物、未来读者 resolve 不了的——票号（`T3`）、`§4-1`、spec / plan / design 文档名、`docs/*-flows/…` 路径，以及纯文字的「见上文」「评审时定的」「上一个 task 的做法」。要说就把实质展开写进来，不写指针。
- **⛔ 「见 X」指针默认不写**：X 只要 go-to-definition 到得了（同文件符号、本文件 `import` 的符号、仓内任何可跳转的实现）就别写——`import` 本身就是路标。**唯一可留**：X 是 go-to-definition **到不了**、又是读懂本行必需的（典型是把不变式的 oracle 指出来：「这条顺序由 `foo.test.ts` 钉住」），只留一行。
- **改到的代码，相邻既有注释与新代码对不上就同步修 / 删。**（`comment` skill 的「改动相邻侧」：范围是 `git diff <base> -U20` 的 context 行里出现的既有注释，判据是那条注释与它现在贴着的代码对不上。这一侧是老注释的例外口子，其余老注释仍然不动。）
- **指令型注释不计预算、也不许删**：`eslint-disable` / `@ts-ignore` / `prettier-ignore`，以及删了会留下空块的那种。
- **这是「写的时候守」，不是「自己跑一遍清理」。** ⛔ 别调 `comment` skill、别去 Read 那个 skill 的文档、别给自己另起一个「清注释」步骤。那个清理 pass 是另一个环节，由主 session 在本票 commit 之后另派一个 fresh-context 代理做——它的判据是「陌生读者冷读」，你读过这些改动，判不了。
- **与项目 CLAUDE.md 里「禁止删除已有注释」那条不冲突，两条管的是不同的注释**：**本纪律只管本票新写的注释**（超预算时删的是你自己刚写的那几条）；**「禁删已有」管本票之前就存在的注释**——那些照旧不许删，唯一例外仍按项目 CLAUDE.md 的原文（注释所述代码已完全移除且无参考价值）。⚠️ 反过来也成立：被你的改动删掉的**既有**注释若属本地四类 why，要恢复。
