# comment — 代码注释纪律与清理（flow 共享）

## 重心：一条测试，一个默认

注释**没有预言机（oracle）**——代码错了测试会红、运行时会崩；注释错了**什么都不会发生**，它静静躺着骗人，可能骗好几年。治理的全部重量压在一条测试和一个默认上：

> **盖住测试**：把这条注释盖住，一个称职的**陌生**读者——只看**代码 + 命名 + 类型 + 结构 + 测试 + 字符串字面量（文案/日志/错误消息/测试名），并顺着 `import` 跳到定义处（go-to-definition）**——还能不能得到同样的信息？
> - **能 → 删。** 默认删；而且是**直接删，不是「压缩成一句 + 留个『见 X』」**——`import` 本身就是路标，读者顺着去。
> - **不能 → 才进入下面「留什么」。**

这条测试**天然跨文件**：定义在别处的东西，归属地是那个文件；在消费方转述它的内部行为 / rationale / 与别的实现的异同，盖住测试**必过**（读者跳过去就知道），删。这是本纪律最像「有用」、最难自觉的一类冗余，它还会漂移（别处一改，转述就错，且无预言机报红）。

**直接推论——「见 X」指针默认删**：一条 `//（见 X）/（详见 X）` 只要 X 用 go-to-definition 到得了——**同文件的符号、本文件 `import` 的符号、仓内任何可跳转的实现**——就**删掉指针本身**。留它 = 承认读者会跳过去，那就让 `import` + 跳转去做，别用一行注释重复这个动作；「某事在 `authScope.ts` 实现 / 在 `rawFetch.ts` 做」这种「在哪做」的导航，本行不靠它也读得懂，一并删。**唯一可留的指针**：X 是 go-to-definition **到不了**、又是读懂本行必需的——典型是**把不变式的 oracle 指出来**（「这条顺序由 `foo.test.ts` 钉住」）或跨仓外部稳定文档，且只留一行。

## 留什么：只有「本地的、跳过去也得不到」的 why

盖住测试删不掉的，才轮到判断留不留。留的下界是四类，每类都必须**同时**满足三个条件——**本文件*拥有*那段代码** ＋ **代码结构表达不了** ＋ **不知道就会改错**：

- **缘由**：为什么这么做（本文件的设计 / 业务 rationale）。
- **否定**：为什么**不**用那个看起来更显然的写法（防好心重构踩回坑）。
- **约定**：本文件承担的调用契约 / 前置条件 / 非局部约束。
- **边界**：非显然的边界、外部系统的坑（第三方 API 怪异、协议、历史兼容包袱）。

**第一个条件是闸门，专治「看着有用其实不属于这里」**：这条 why 描述的那件事，是**本文件拥有的代码**，还是本文件只是*调用*的别处代码？别处拥有 → 归那边、删；本地拥有 → 才可能留。

留的也要**放置就近**：贴在**最可能被改错的那一行**正上方，别堆函数 / 文件头——堆头注释会让多条各自合规的约束叠成长条、淹没文件，就近天然把它们分散。

⚠️ 四类是**下界，不是许可证**：先过盖住测试，过不了就删；别把注释硬套成「这也算缘由/边界」来免死。

## 留之前先问：能不能变成会失败的代码

能搬进有预言机的载体的，别留注释——「必须非负 / 可能为 null / 只能这几种取值」→ 类型（非空 / 枚举 / branded）；「必须已初始化 / 已排序」→ `assert` / 契约。搬进去代码一变就报错，强过一条无人校验、会腐坏的注释。搬不动的，才留最短的一句；散文 rationale 的对错最终只能靠人审，不粉饰。

## 删的常见长相（都是盖住测试的实例，不是另立的规则）

- **异地归属**：替调用的别处解释它的内部（「骨架整份在共享的 `createX`」「与 web4 逐字节等价」「共享层 `status===0` 恒返整份的理由是…」）→ 归定义处，删；本文件只留「本端提供哪两样」这种消费方本地事实。
- **进程指代**：指向 flow 执行期临时产物、未来读者 resolve 不了的——符号（`T3` / `§4-1` / `FP-006`）、文档名（`plan.md` / `design.md`）、甚至纯文字（『见上文』『评审时定的』『上一个 task 的做法』）→ 删或展开成实质，不写指针。
- **复述 what**：`// increment counter` 配 `counter++`；和下方 `dialog.detail` / `log.info` / 错误消息讲同一件事（删注释、留文案）。
- **注释间互指**（『见上面』『同上』）、**标榜**（『高内聚』『optimised』）、**复读已被 lint / 团队约定强制的规则**、**背景小作文**（来龙去脉写成段落）、**注释掉的代码**、**分区标题**、**签名复述**。

**禁误删（保留清单）**：本地四类 why、非显然约束、外部稳定文档 / issue 链接、**指令型注释**（`eslint-disable` / `@ts-ignore` / `prettier-ignore` / 删了会留空块的）。

## 为什么必须有「会真删的 pass」，而不是靠提示词

实测：一个把「默认不写 + 只留四类 + 禁进程指代」整份写进提示词的 flow，真实产出的源码仍是 **24% 密度 + 54 处它自己明令禁止的进程指代**。**多写注释是模型的底层倾向（RLHF 冗长偏好 + 训练惯例），提示词压不住**。所以 load-bearing 的不是「写更好的规则」，而是一个**专职、会真删、由 fresh-context 子代理执行**的清理 pass——**冷读代码的陌生人才做得了盖住测试**，攥着实现上下文的作者做不了（他「知道」每条为什么重要，恰恰判不了「陌生读者觉不觉得有价值」）。这个 pass 在每个 flow 的 CR 阶段被**显式调用**执行，机械细节见下。

# 执行参考（承重的管道，运行时查，不占重心）

> 上面是脊椎，任何执行者先内化「盖住测试 + 删默认 + 只留本地 why」；下面是让这个 pass 正确落地的机械约束，跑的时候查。

## 调用与范围

- **只显式调用**（CR 阶段 `/ai-flow:comment <范围>` 或用户手动），绝不关键词自动触发、也不靠 stage 提示词「提一嘴」。专职单一职责，才比「多轴评审里被稀释的一条」可靠。
- **范围 = 已追踪改动 ∪ 未追踪新文件**：已追踪 = `git diff <base>`；未追踪 = `git ls-files --others --exclude-standard` 的新建文件，**其每一行都算新增**。⚠️ 未追踪必须单列一路——`git diff` 不比对未追踪文件，而真实场景里新功能的绝大多数注释就在这些新建文件里（stage-3 改动留工作树不 commit、stage-4 `git reset` 后呈未追踪），只跑 `git diff` 会让它们整体逃过本 pass。
- ⚠️ **禁 `git add -N .` 把未追踪塞进 diff**：它改 index、把文件移出 IDE 的 Untracked 分组，破坏 stage-4「开发者在未暂存组亲审、语言服务可用」。要覆盖未追踪走下面 Step 1 的 B 路。
- ⚠️ **测试文件排除**（`*.test.*` / `*.spec.*` / `__tests__/` / `tests/` 等）：不扫、不删、不做 Step 3。因为①盖住测试正是把「测试」当代码来判生产注释冗余，反过来治理测试注释是拿判据反噬它；②测试的回归锚注释（说明某 case 对应哪个历史缺陷）形似「复述测试名」最易被误杀，却恰恰删不得；③注释与测试脱节代价小（测试挂了立刻暴露）。写时纪律仍适用，只是本 pass 不管。

## 执行模型：fresh-context `sonnet` 子代理群

- **必须派 fresh-context 子代理执行，主 agent 不做删留判断**（理由见脊椎「为什么必须有会真删的 pass」）。⚠️ fresh-context 只保证子代理无会话记忆，堵不住主 agent 把语境塞进 dispatch prompt：**派发指令只给文件路径 + 范围（base SHA / 文件清单），不得描述本次改了什么 / 为什么 / 哪个 task / 任何设计理由**——带了，冷读假设当场击穿。
- **模型写死 `sonnet`**：三档实测——`haiku` 粗判对，但压缩时会凭半懂**把技术事实改飘**（悄悄换掉机制名），注释没预言机、这种静默错误直接 ship，最毒；`opus` 对删注释的增量不值那价。固定 sonnet、不上浮不下沉。
- **派发（一子代理认领一批文件，不是一个文件一个）**：① 主 agent **选文件并切批**——选：含代码且注释非平凡，跳配置 / 生成物 / lockfile；切：把选中的文件分成若干批（这是枚举 / 分配，不是删留判断）。② **一子代理认领一批、并发 ≤5**：并发上限管内存（再多会把机器打崩，实测教训）；**切批而非逐文件派发**——否则 N 个文件 = N 次起子代理 + N 次重读本 skill，纯浪费，切批把它压成「几个子代理各扫一批」。**批间文件集不相交 → 无写冲突**；**单批文件数 ≤ 8**——一个子代理塞太多，context 会撑爆、越往后判得越差（per-file 冷读被稀释），宁可多切几批；批数 > 5 就分轮、轮间串行。③ 子代理在自己这批里**逐个文件处理、每个都当独立冷读来判**（盖住测试是 per-file 的，别让前一个文件的上下文污染后一个——这是「陌生读者」属性在批内的保命条）；可读全仓判归属地（定义处 / 测试 / 别处 JSDoc），⚠️ 但**排除本 flow 临时产物目录（`docs/*-flows/`）、不得拿「flow 文档里写了」当依据**。④ 每批回：逐文件的精简改动 + Step 3 反问答案 + 机械搬记录 / 搬迁候选（若有）；**Step 4 归主 agent**统一做。
- ⛔ **dispatch prompt 里必须写死「不要**执行** typecheck / lint / 测试**命令**」**（⚠️ 措辞要点出「执行」和「命令」——**读测试源码仍是「盖住测试」的必需输入**，见脊椎那条；写成「不要跑任何测试」会被读成「不要参考测试」，判据当场垮掉）。 「Step 4 归主 agent」写在本文里，子代理看不到——它只看得到你派发的那几百字，而「⛔ 不许改非注释代码」这条会让它自发跑验证来自证。实测一轮 10 个子代理有 8 个跑了 tsc / eslint / vitest（共 17 次），其中一个跑完 61 个测试文件 1150 条用例，只为确认自己删了几行注释；这些验证落在子代理 92–152K 上下文的后段，单次往返 0.2–0.3M——**贵在频次不在单价**。删注释不该破坏任何东西，真破坏了也会在你 Step 4 的统一重测里暴露——那里跑一次，不是每个子代理各跑一次。
- ⚠️ **「选文件」里机器算得出的部分用 shell 算，别为它派子代理。** 注释行数 / 占比 / 本轮新增注释行数都是 `git diff` + `awk` 一条命令的事。实测一次运行把「值不值得清理」整个交给 14 个筛选子代理（15.91M / 367 个文件——注意这批人和上一条那 10 个清理子代理不是同一批），事后核对：367 个里 238 个是纯阈值命中，子代理的语义判断相对纯算术只改变了 29 个答案（7.9%），而下游只消费了路径、判据和理由全被丢弃。**要派子代理筛，就只把算术判不了的那部分派给它。**

⚠️ **并行安全：删「因别处已记录」只认预言机、不认另一条注释**（本条只管**跨文件**；同文件互指仍按脊椎合并）。以「别处已保证」为由删除，两条都要满足：①**是真预言机**——测试 / 类型 / 运行时断言 / 分阶段 API（「当前调用点恰好这么写」**不算**，没强制、改错不报红）；②**内容对得上**——那预言机断言的正是这条注释讲的那件事（测试测「传未排序会抛异常」≠ 注释讲「必须已排序否则结果错」）。「别处」只是**另一条散文注释**时**不许删**——它可能正被另一个并行子代理以对称理由删掉，两边同删则知识两处蒸发（串行不会：后删的读到前者已空、只剩自己 → 留）。唯一副本是注释时，留。

## Step 1 · grep 抓符号类候选（辅助、非穷尽）

由子代理**限定到自己那一个文件**跑（A 路加 `-- <该文件>`，B 路直接 grep 该文件）。只抓**符号类**进程指代当候选，抓不到文字类（那是 Step 2 语义的活）；**允许误判放行**（命中合法泛型 `T2` / 常量名 / 指向可独立 resolve 的外部稳定文档 → 不动）。
```sh
PAT='(//|/\*|\*).*([Tt]ask [0-9]|[^A-Za-z]T[0-9]|[^A-Za-z]U[0-9]|[Pp]hase [0-9]|§[0-9]|D-[0-9]|FP-[0-9]|/simplify|owner 拍板|评审揪出|见上文|plan\.md|design\.md|architecture\.md)'
git diff <base> -- <file> | grep -E '^\+' | grep -nE "$PAT"     # A) 已追踪
grep -InE "$PAT" <file> /dev/null                                # B) 未追踪新文件（全文皆新增）
# 全范围跑 B 路时必须 git ls-files --others --exclude-standard -z 并排除 flow 文档目录，
# 否则会命中并误删 candidates.md/tickets.md 这类 Markdown 正文（$PAT 的 `\*` 匹配 `* 列表项`）。
```

## Step 2 · 语义判断（双向）

子代理**双向**核自己文件：**新增侧**（diff `+` 及未追踪全文）逐条按脊椎判——删异地归属 / 进程指代（含文字类）/ 复述 what / 标榜 / 背景小作文，能搬则搬，顺带核**失效**（注释与相邻代码对不上）；**删除侧**（diff `-`）核**误删**——被本次改动删掉的若属本地四类 why → **要求恢复**（防实施子代理「重写时把 why 一把删光」，这就是很多项目「禁删注释」规则要防的，本 skill 自带这道反向守卫）。默认**不主动删既有老注释**（Step 3 触发时才放开，见下）。

## Step 3 · 文件级综合（会合并重写；治「每条都合规、整体却冗余」）

逐条过滤产不出「把 5 条并成 2 句」，且逐条判断有**锚定效应**（盖住这条时其余还在、跨条重复看不见）。文件满足任一即追加本步：**注释 ≥ 8 行 / 占比 ≥ 15% / 任一符号超硬预算**。顺序 **闭卷 → 对齐 → 搬**（反了锚定效应就回来）：
- **闭卷**：把现有注释全当不存在，只读代码问「一个没有本次上下文的维护者，会在哪里改错？」——每点写一句 = 理想集合。
- **对齐**：现有注释映射到理想集合，多对一 → 合并，理想集合有而没覆盖 → 补。⚠️ **对不上不直接删**——先反问「它讲的改错点我闭卷为何没想到？」是它不构成改错点（删），还是我漏了（补进理想集合、留）？少了这步，本步默认就从「不确定就留」反转成「对不上就删」，会理直气壮删掉真 why 且重测抓不到。
- **搬**：理想集合里「前置条件 / 调用顺序 / 取值范围」类先试搬成断言 / 类型。⚠️ **只做本文件内自包含的机械搬**（字面量→本文件常量、硬编码键→引用已有常量；目标常量在别文件可加一行 `import`、那文件不动）；需改**未分配文件**（改签名牵动别处调用点）→ 不做、登记「搬迁候选」。当场搬的**必须与删注释分列记入 review**，供 Step 4 核。
- **预算复核**：理想集合超「每符号 3 条」→ 重排优先级、只留最会改错的 3 条。
- ⚠️ **老注释口径**（Step 3 专属）：本步全部注释进对齐，老注释**可删 / 可合并、但不得改写措辞**（别人写对的表达不动）。

⚠️ **诚实边界**：闭卷重写同样是 LLM 概率判断、会误判（把「漏看重复」换成「可能误删一条 why」），没让注释变得可自动验证。误删靠 Step 4 + 保留清单兜；保留清单里的（指令型注释 / 外部稳定链接）一律照抄、不进闭卷。

## Step 4 · 汇总核实 + 删完重测（主 agent）

**以 `git diff` 为唯一事实源、不采信子代理自报**（实测：子代理会编造报告——声称改了没碰的文件、虚构原文）。逐个核：①实际改动文件 = 分配给它的（未分配文件零改动）；②测试文件零改动；③非注释行改动——未触发「搬」的文件应为 0，触发且搬了的须逐一对应 review 记录的搬迁项，**对不上即不可信**（越权或漏记都不采信）、回退（动作与诊断解耦，别把漏记当违规）。核完再重跑 typecheck + lint + 范围测试（删注释不该破坏任何东西；误删指令型注释在此暴露）。
**记录进本 stage 的 review 产物**（分节由各 flow 自定）：删除条目附反问答案、机械搬逐条、未做的搬迁候选、以及——若某文件 Step 3 对齐**产不出任何增删**（常见于保留清单主导的文件），须写明「对齐无变更，因现有注释已各自映射理想集合、无重叠」，不许拿「保留清单太多」当跳过闭卷的偷懒出口。

## 写时预防 + 评审标记（便宜的两层，不替代上面的 pass）

- **实施子代理写时**：dispatch prompt 传入脊椎判据（默认不写、只留本地四类、能搬先搬）+ **硬预算**——每个函数 / 类 / 方法 / 顶层常量的**归属注释 ≤3 条、每条 ≤2 行**（**不论物理位置**：头注释 + 函数体内贴该符号的注释合计；「放置就近」不等于绕过预算），文件顶另许 1 条。超了必须合并或删（可数上限模型才压得住，也是 Step 3 的客观触发条件）。
- **评审子代理**：读 diff 时顺带双向标记（新增噪声该删、误删 why 该恢复），report-only。**别把治理押在这层**——feat-flow 就是把它做成多轴评审里被稀释的一维，结果 54 处进程指代溜过。

## 边界（诚实标注，不对上游夸大）

- **进程指代**：符号类有 grep 前哨、文字类靠语义，覆盖绝大部分但形态无穷，**不保证 100%**，允许极少漏网。
- **跨文件重复的散文注释合不了**：并行安全规则的代价——两文件各留一条讲同一件事的散文，没机制并成一条（合并只在同文件内）。为消互删竞态付的确定成本，宁可各留一条真 why，不冒双删删空。
- **保留清单主导的文件，Step 3 被架空**：整文件几乎全是结构性论证时，闭卷没有可挑战对象、退化成逐条过滤，同文件内两条都属保留清单的重复抓不到。要治只能单独放开该文件保留清单重跑 + 每处删除附反问 + 人审，默认不做（Step 4 要求这类文件留痕交底）。
- **为什么不做 fail-closed gate**：进程指代形态无穷，固定 grep 既误伤合法代码又漏文字类；判断本质是语义，该由本 skill 承载并**允许放行**，不是机器闸。
- 能自动验证的只有「搬进类型 / 断言」的部分；散文 rationale 最终只能靠人审。本 skill **大幅降低**噪声与腐坏面，但**不消除**验证不对称。
