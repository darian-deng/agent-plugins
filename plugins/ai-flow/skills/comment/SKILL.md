# comment — 代码注释纪律与清理（flow 共享）

## 教训先行：为什么光有规则不够，必须有会真删的清理

**实测证据**：一个内联了完整注释规则（"默认不写 + 只留四类 + 自包含禁 flow 指代"）的 flow（feat-flow），最近一次真实产出的**源码**（62 文件、排除测试）仍是 **24.3% 注释密度 + 54 处 `Task N` / `plan.md` / `design.md` / `§` 这类它自己规则明令禁止的进程指代**。

结论：**注释规则单靠提示词不可靠——AI 读了照样违反**（多写注释是 RLHF 冗长偏好 + 训练数据惯例的底层倾向，不是提示词能压住的表层习惯）。所以本 skill 的重心**不是"写一条更好的规则"**，而是**一个会真删的、专职单一职责的清理 pass**（用法三）。规则（用法一/二）只做预防和标记，**清理 pass 才是 load-bearing 的强制层**。任何 flow 引用本 skill，都必须在 CR 阶段跑用法三，不能只把规则塞进 prompt 就算数。

## 为什么这条纪律难（先讲清楚，避免机械执行）

代码有测试 + 运行时做**预言机（oracle，能自动判对错的真值来源）**；注释**没有任何预言机**——准确性、是否失效、是否恰到好处，没有 CI 能判。注释本质是一条**无法被测试的自然语言断言**。治理只有三条路，按优先级：

1. **能搬进有预言机的载体的，搬走**：「参数必须非负 / 可能为 null / 只能是这几种取值」→ 类型（非空类型、枚举、branded type）；「调用前必须已排序 / 已初始化」→ `assert` / 契约。搬进去代码一变就报错，好过留一条会腐坏且无人校验的注释。
2. **搬不走的，最小化**：写得越少，腐坏面、审查面越小。
3. **剩下的靠人审**：散文 rationale 的对错没有自动手段能验，这是本质困难，不粉饰。

**注释不是越多越安全，是越少越安全。**

## 判据一：该不该写（盖住注释测试，delete-biased 默认）

> **把这条注释盖住，一个懂这门语言的称职读者，光看代码能不能得出同样信息？**「代码」= 类型 + 命名 + 结构 + 测试 + **字符串字面量**（用户可见文案 / 日志消息 / 错误消息 / 测试名）。⚠️ 最后这项最易漏：一条注释常和它下方的 dialog `detail`、`log.info`、错误消息讲的是同一件事——那就是冗余，删注释留文案。
> - 能 → **冗余，删**（默认删，不是默认留）。
> - 不能 → 它补的是判据二「四类」里的哪一类？答得出才留，答不出也删。

## 判据二：留什么（四类，唯一的保留下界）

只有代码**结构上表达不了**、且未来读者不知道就会改错的信息才留：

- **缘由**：为什么这么做（设计 rationale / 业务约束由来）——代码只表达 what，表达不了 why。
- **否定**：为什么**不**用那个看起来更显然的写法——防后人「好心重构」踩回坑。
- **约定**：调用契约 / 前置条件 / 非局部约束（如「必须先调 A 再调 B」——任何语言都无法在代码里表达调用顺序）。
- **边界**：非显然的边界条件、外部系统的坑（第三方 API 怪异行为、协议约束、历史兼容包袱——代码里只看得到 workaround、看不到原因）。

注释要比代码**高一个抽象层级**：和代码同层（复述 what）必然冗余；高于代码层（why / 非局部 / 契约 / 外部坑）才有价值。⚠️ 四类是**保留下界，不是许可证**——别把任何注释都硬套成「这是缘由/边界」来豁免删除；先过判据一，过不了就删，四类只兜住判据一都删不掉的那一小撮。

**放置就近**：该留的约束，贴在**最可能被改错的那一行代码**正上方，别堆在函数 / 文件头。注释离危险点越近，后人改到那行时越躲不开它——如「⛔ 别改成 `< 4.0.0` 下界比较，会抹掉线上老用户」应压在那个比较表达式上方，而不是埋在函数头注释的一大段里。堆头注释还会让多条约束叠加成长条（每条单看都合规、整体却淹没文件），就近拆开天然分散了它们。

## 判据三：删什么（命中即删或改写，附真实例子）

- **进程指代（最优先，flow 最易漏）**：任何指向 flow 执行期临时产物的指代。**判断基准是语义、不是固定符号表**：未来读者（没有本次 flow 上下文、不翻 `docs/*-flows/`）**能不能 resolve 这个指代**？不能 → 它是进程指代，删或展开成实质。形态**不限**：符号（`T3` / `P2` / `§4-1` / `U10` / `FP-006` / `D-xx`）、文档名（`plan.md` / `design.md` / `architecture.md`）、**甚至纯文字**（『见上文』『按规划文档』『评审时定的』『上一个 task 的做法』）——文字类符号表抓不到、靠语义识别。**要留背后实质就展开写，不写指针。**
  - 真实反例（feat-flow 漏网的）：`// privacy_local 联查（Task 16 FP-006）：详情页据此渲染 PrivacyTag` → 删 `（Task 16 FP-006）`、留缘由半句。`// 断言硬 contract（plan.md Task 8 decisions）` → 删指针，contract 本身非显然就展开写它是什么。
- **注释间互指**：`// 见本文件 X 的头注释`、`// 详见上面的常量注释`、`// 同上` → 互指本身就是「同一件事写了两遍」的自证；把两处**合并到一处**、删掉指针。别因为它写得正式（带符号名、不是『见上文』）就觉得不算违规。
- **复述 what**：`// increment counter` 配 `counter++`、`// 返回结果`、把代码翻译成中文/英文。
- **标榜设计**：`// 高内聚自管`、`// optimised version`、`// 改进后的实现`。
- **复读已强制规则**：lint / 路径规则 / 团队约定已强制的（「禁 try/catch」「跨域动态 import」）——工具已拦，注释是噪声。
- **背景小作文**：把改动来龙去脉写成段落 → 砍到只剩「不知道就会改错」的那一句 why，其余属 commit message / PR / design.md。
- **注释掉的代码**、**分区标题**（`// ===== HELPERS =====`）、**签名复述**（`// 接收 X 返回 Y`）。

**保留清单（禁误删）**：自包含的四类 why、非显然约束、外部稳定文档/issue 链接、**指令型注释**（`eslint-disable` / `@ts-ignore` / `prettier-ignore` / 删了会导致空块的注释）。

## 自包含硬规则

注释只用**未来读者手上有的信息**。commit message 同此。禁指向 flow 内部临时产物（见判据三「进程指代」）。flow 内部归档（task-reports.md / candidates.md 等）不受此限。

## 用法一：实施子代理写时预防（便宜，但不可靠，别当唯一防线）

派实施子代理时把本 skill 判据传入 dispatch prompt：默认不写、只留四类、自包含、能搬类型/断言的先搬。这是最便宜的一层——但 feat-flow 证明**光靠它会漏**，它只减少入流量，不替代用法三。

**硬预算（给数字，不给态度）**：**每个函数 / 类 / 方法 / 顶层常量（不论是否导出）**的**归属注释 ≤3 条、每条 ≤2 行**——**不论物理位置**：头注释 + 函数体内贴着该符号逻辑的注释**合计**算这一份名额；文件顶部另许 1 条。⚠️ 判据二「放置就近」把约束从头注释挪进函数体，**不等于绕过预算**，它仍占这个符号的 3 条名额。超了就是**必须合并或删**，不是「酌情」。为什么用数字：「默认不写」「尽量精简」是态度性指令，会被 RLHF 冗长偏好消解（开头那份实测证据就是这么来的）；可数的上限模型压得住，也给了用法三一个客观触发条件——**超预算即触发下面 Step 3 的文件级综合**。

## 用法二：评审子代理标记（辅助，不是主力）

评审子代理读 diff 时**顺带**按判据双向核注释（新增噪声该删、误删的四类 why 该恢复），report-only。⚠️ **别把注释治理押在这一层**——feat-flow 就是把它做成多轴评审里被稀释的一个维度，结果 54 处进程指代溜过去。它只做「提前标记」，真正的删由用法三兜底。

## 用法三：专职清理 pass（load-bearing，CR 阶段由 flow 显式调用）

**由 flow 在 CR 阶段显式调用本 skill 触发（`/ai-flow:comment <范围>`），不是靠 stage 提示词"提一嘴"。** 一个**专职、单一职责**的清理动作，只干注释这一件事（正因单一职责，才比"多轴评审里的一条"可靠）。

**清理范围 = 已追踪改动 ∪ 未追踪新文件**：已追踪那半边是 `git diff <base>`（或当前未提交改动），未追踪那半边是 `git ls-files --others --exclude-standard` 列出的新建文件，**其每一行都算新增**。⚠️ **未追踪新文件必须单列一路**——`git diff` 只比对已追踪文件，而本 skill 的两个真实调用场景里新建文件恰恰都是未追踪：stage-3 每票的实施子代理「改动留工作树、不 commit」，stage-4 环节 C 在 `git reset` 之后新文件呈未追踪。一个新功能里绝大多数注释就在这些新建文件中，只跑 `git diff` 会让它们整体逃过本 pass。

⚠️ **测试文件排除在本 pass 之外**（与下面排除 flow 文档目录并列的**范围级**排除）：`*.test.*` / `*.spec.*` / `__tests__/` / `tests/` / `test_*.py` 等按项目约定识别的测试文件，本 pass **不扫、不删、不做 Step 3**。三条理由：① 判据一正是把「测试」算作代码来判生产代码注释冗余——反过来治理测试自己的注释是拿判据反噬它的依据；② 测试里的**回归锚注释**（说明某 case 对应哪个历史缺陷的机理）形式上极像「复述测试名」，最容易被判死，而它恰恰删不得——测试名只说测什么，说不了"为什么这个 case 必须存在"；③ 注释与代码脱节在测试里代价小（测试挂了立刻暴露），不值得为它承担误删风险。**但写时纪律仍适用**：测试文件里同样别写复述 what 的废话，只是硬预算与清理 pass 都不管它——「不扫」不等于「放任」。

⚠️ **禁止用 `git add -N .` 把未追踪文件塞进 diff**——看着省事，实则有害：stage-4 环节 C 依赖「保持 unstaged，开发者在 IDE **Changes（未暂存）**组里亲审、语言服务可用」，`git add -N` 会改动 index 并把这些文件移出 Untracked 分组，是这个 flow 明确不要的副作用。要覆盖未追踪文件，走下面 Step 1 的 B 路。

**执行模型 · fresh-context `sonnet` 子代理群（写死 sonnet、最多 10 并行）**

本 pass **必须由 flow 主 agent 派 fresh-context 子代理执行，主 agent 自己不做删留判断**。原因直指判据一：「盖住这条注释，一个**没有本次上下文的读者**能否从代码得出同样信息？」——而主 agent 攥着整条实现的来龙去脉，它「知道」每条注释为什么重要，恰恰**判不了「陌生读者是否觉得有价值」**。实测教训：带满 context 的主 agent 手做的版本，会出于「我知道这重要」而留下 fresh 子代理判定该删的注释（甚至该查有没有测试兜底却没查）。**冷读代码的子代理，才是判据一在 agent 层的落地。**

⚠️ **fresh-context 只保证子代理没有会话记忆，堵不住主 agent 亲手把语境塞进 dispatch prompt**：派发指令**只给文件路径 + 清理范围（base SHA / 文件清单），不得描述本次改了什么 / 为什么改 / 这是哪个 task / 任何设计理由**——一旦带了，冷读假设就在提示词这层被击穿，fresh-context 机制对此无能为力。这是本执行模型的命门，dispatch 模板必须照此收口。

**模型写死 `sonnet`，不是「sonnet 或更强」**：三档实测——`haiku` 能做对粗判（保住语义陷阱、删跨文件冗余、也会主动读调用点），但**压缩注释时会凭半懂重写、把技术事实改飘**（把某机制名悄悄换成别的），而注释没有预言机、这类静默错误不会被任何测试抓到、直接 ship，是最毒的失败模式；`opus` 对「删注释」这件事的增量不值那个价（开发者明确不愿为删注释付 opus）。`sonnet` 是既安全又不浪费的档，**固定用它，不上浮不下沉**。

**派发（在 flow 的每个清理调用点做——grill 每票 / 收尾，feat 收尾；文件多时并行加速尤其有用，每票场景往往只有一两个文件、fan-out 自然退化成 1 个子代理）**：
1. **智能选文件**：从下面「清理范围」里挑真正值得审的——**含代码且注释非平凡**的文件；跳过纯配置 / 生成物 / lockfile（测试文件与 flow 文档目录已在范围级排除，不必再挑）。
2. **一文件一子代理、最多 10 个并行**；范围内文件超 10 个就分批（按注释体量优先审重的）。**每个子代理只写自己那一个文件**（彼此不碰同一文件 → 无写冲突），但**可读全仓**——判跨文件冗余必须能读调用点 / 测试 / 别处 JSDoc。⚠️ 但**排除本 flow 的临时产物目录（`docs/*-flows/` 等），且不得拿「flow 文档里写了」当「已记录 / 可从代码推导」的依据**——未来读者不翻这些，冷读假设也不认它们（判据三已界定读者「不翻 `docs/*-flows/`」）。
3. 每个子代理独立跑下面 **Step 1–3**（只针对自己那个文件）、回精简后的改动 + Step 3 反问答案清单 + **机械搬记录（若有）+ 未做的搬迁候选（若有）**（这两项是 Step 4 汇总核对与登记的输入，子代理不带回来主 agent 就无从核）；**Step 4 归主 agent**：所有子代理回齐后**统一跑一次全量重测**（typecheck / lint / 范围测试一把过，子代理不各跑）。超 10 个文件分批时**批次按顺序执行**——并行安全是类别禁令、不依赖时序，故即使并发也扛得住，但显式串行省得读者自己推导这层健壮性才敢放心。

⚠️ **并行安全：删「因别处已记录」只认预言机，不认另一条注释**（本条只管**跨文件**的「别处」；**同文件内**的注释间互指仍按判据三合并处理，不受此限——同文件由单个子代理独占、无跨代理竞态）。子代理想以「这条约束别处已经保证了」为由删除时，两个条件**都**要满足：
- **是真预言机**：「别处」必须是**真会失败的机制——测试 / 类型 / 运行时断言 / 分阶段 API（返回受限句柄那种）**。⚠️ **「当前几处调用点恰好按这个顺序写」不算**——它没有任何强制，未来新增一个顺序写反的调用点不会编译错、不会测试红，正是判据二说的「调用顺序任何语言都表达不了」那类，仍按**约定**类**留**，别拿它当 oracle（与判据二对齐，别自相矛盾）。
- **内容对得上**：那个预言机断言的**正是这条注释讲的那件事**，不能只看类别。反例：注释讲「必须传已排序数组否则二分查找结果错」，测试却只覆盖「传未排序会抛异常」——类别对（是测试）、内容不对（测的是防御分支、不是排序假设），**不许据此删**。

「别处」只是**另一条散文注释**时**不许删**——那条可能正被另一个并行子代理以对称理由删掉，两边同删则知识从两个文件一起蒸发（串行天然不会：先删的读到后者还在，后删的读到前者已空、只剩自己这份 → 保留；并行读的都是原始快照、两份都在，于是双删）。**唯一副本是注释时，留。** 这条同时让「删冗余」更严谨：冗余对预言机（且内容对得上）= 安全删，冗余对另一条会腐坏的注释 = 不删。

**Step 1 · grep 抓符号类候选（辅助、非穷尽）**
⚠️ **谁跑 / 什么范围**：文件选取（哪些文件进清理、怎么分给 10 个子代理）由**主 agent** 做——这是**枚举**、不是删留判断，不违反上面「主 agent 不做删留判断」。每个**子代理**把下面的 grep **限定到自己那一个文件**跑（A 路加 `-- <该文件>`，B 路直接 grep 该文件），**不重扫全仓**，命中也只看自己文件的。下面脚本给的是全范围形态，按此收窄到单文件即可。
先跑 grep 抓本次**新增**注释里**符号类**进程指代当候选（flow 内置、自包含，不依赖项目装 lint）。⚠️ 它**只抓符号**（`T3` / `§` / `design.md` 这类），**抓不到文字类**（『见上文』『按规划文档』）——那是 Step 2 语义兜底的活；grep 只是廉价前哨、不是防线。**A / B 两路都要跑**，漏掉 B 就等于漏掉整批新建文件：
```sh
# 不用 \b（BSD/macOS grep 不可靠）；宽松匹配当候选finder
PAT='(//|/\*|\*).*([Tt]ask [0-9]|[^A-Za-z]T[0-9]|[^A-Za-z]U[0-9]|[Pp]hase [0-9]|§[0-9]|D-[0-9]|FP-[0-9]|/simplify|owner 拍板|评审揪出|见上文|plan\.md|design\.md|architecture\.md)'

# A) 已追踪改动：只看 diff 的新增行
git diff <base> | grep -E '^\+' | grep -nE "$PAT"

# B) 未追踪新文件：整个文件所有行都算新增，全文跑同一套注释 grep
#    --exclude-standard 已过滤 gitignore；-z / -0 保证文件名带空格也不断。
#    不要用 `git status --porcelain | awk '{print $2}'`——带空格的文件名会被截断。
#    末尾的 /dev/null 让「一个未追踪文件都没有」时 grep 不至于退化成读 stdin 卡住。
#    grep -I 跳过二进制文件（未追踪里常有图片/产物，二进制命中毫无意义）。
#    ⚠️ 必须限定范围：裸跑会捞到全仓每一个未追踪文件，其中 flow 自己的记账产物
#    （candidates.md / tickets.md 等，stage-3 刻意留工作树不 commit）是 Markdown，
#    而 $PAT 的第一段 `\*` 会命中普通 Markdown 列表项 `* …`——本 pass 会真删，
#    在这些文件上误命中的后果是删掉正文。所以照调用方的范围排除 flow 文档目录。
FLOWDOCS='docs/grill-flows'   # ← 换成本 flow 的产物目录（feat-flow 用 docs/feat-flows）
git ls-files --others --exclude-standard -z -- . ":(exclude)$FLOWDOCS/**" \
  | xargs -0 grep -InE "$PAT" /dev/null
```
命中是**候选、逐条判**：指向 flow 临时产物 → 删指针 / 展开 / 整条删。**允许误判放行**——参考：命中项若是代码里合法的泛型（`T2`）/ 常量名，或指向未来读者能独立 resolve 的外部稳定文档，即误命中，**放行不动**。

**Step 2 · 语义判断（承载绝大部分兜底，双向）**
子代理**双向**核自己文件的注释（diff 的 `+` 新增侧 / `-` 删除侧；未追踪新文件按「全文皆新增」处理，没有删除侧、只走下面第一条）：
- **新增注释（diff `+`，以及未追踪新文件里的全部注释）** 逐条按判据一/二/三判——**含 grep 抓不到的文字类进程指代**（『见上文』『按规划文档定的』，靠语义识别）、复述 what / 标榜 / 背景小作文 → 删，能搬类型/断言的 → 搬或标记，顺带核**失效**（注释与相邻代码是否已对不上）。
- **删除注释（diff `-`）** 核误删——被本次改动删掉的若属四类 why / 非显然约束 → **要求恢复**（防实施子代理"重写时把辛苦的 why 一把删光"，这正是很多项目"禁删注释"规则要防的失效；本 skill 自带这道反向守卫，flow 无需另配）。
本 pass 默认**不主动删既有老注释**（只按上面两条：删新增噪声 + 恢复被误删的 why），误删风险由 Step 4 + 保留清单兜。**受限例外**：同一文件内、当新增注释与某条既有注释讲同一件事时，允许把两条**合并**（可以改既有那条）——只放开「同一文件 + 同一件事 + 合并」这一个口子，**不是**授权重写全文老注释。理由：跨 ticket 逐步长出来的文件，后续票只审自己的新增，前面留下的永远算「老注释」→ 冗余跨票累积、无人看全貌。

**Step 3 · 文件级综合（会合并重写；治「每条都合规、整体却冗余」）**
Step 1/2 都是**逐条过滤器**，而过滤器在数学上产不出「把 5 条合并成 2 句」；且逐条判断有**锚定效应**——判据一把「这条」盖住时，它周围其他注释仍然存在，跨条重复看不见。所以文件满足任一条即追加本步：**注释 ≥ 8 行**、**注释占比 ≥ 15%**、或**任一符号超上面的硬预算**。顺序是闭卷 → 对齐 → 搬，**顺序反了锚定效应就回来了**：
- **闭卷构造理想集合**：把该文件现有注释**全部当作不存在**，只读代码（含字符串字面量 / 日志 / 测试名），问「**一个没有本次 flow 上下文的维护者，读这份代码会在哪里改错？**」——每个会改错的点写一句，这个集合就是理想集合。
- **对齐（默认方向：拿现有注释挑战理想集合的完备性，而不是拿理想集合裁决现有注释）**：现有注释逐条映射到理想集合。多条映射到同一条 → **合并成一条**；理想集合有、现有注释没覆盖的 → 补一条。**对不上任何一条时不直接判删**——先反问一次：「它讲的那个改错点，我闭卷时为什么没想到？」是它其实不构成改错点（→ 删），还是**我的理想集合漏了**（→ 补进理想集合，注释留下）？现有注释是前一个作者留下的信号，可能带着你闭卷时没有的上下文。⚠️ 少了这一次反问，本步的默认动作就从全 skill 的「不确定就留 why」**反转**成「对不上就删」，而依据只是一次 LLM 闭卷猜想——闭卷漏想到一个风险点，那条真 why 就会被理直气壮删掉，且 Step 4 重测抓不到（删散文 why 不会让测试变红）。
- **搬**：理想集合里属于「前置条件 / 调用顺序 / 取值范围」的，**先试搬成断言或类型**（本文开头三条治理优先级的第 1 条），搬成功就不必写注释。这一步最容易被跳过——它要改代码，而清理 pass 的心智容易缩成「只删注释」。⚠️ **两条边界**：① **只做本文件内自包含的机械搬**（字面量→本文件常量、硬编码键→引用已有常量）；凡需要改动本子代理**未分配的文件**（如改调用签名会牵动别处调用点）——一文件一子代理物理上就做不完，**不做、只登记为「搬迁候选」**（归宿见 Step 4）。目标常量若定义在别的文件，**允许在本文件新增一行 `import` 引用它**（那个文件本身不动，仍算自包含）；若该常量**不存在、需新建**，超出机械搬范围，归搬迁候选。② 当场做的机械搬**必须与删注释分列记入 review 产物**（搬了哪条约束、进了哪个断言/类型），供 Step 4 的 git diff 核对——无留痕的隐性代码改动正是要防的。
- **预算复核**：理想集合本身超「每个符号 3 条」时，别照写，回去重排优先级、只留最会改错的 3 条。

⚠️ **老注释口径（Step 3 专属，可单独回退）**：Step 3 触发时，范围内文件的**全部注释都进对齐**，含既有老注释——老注释**可删、可合并，但不得改写措辞**（别人写对的表达不动）。Step 2 末尾「不主动删既有老注释」约束的是那一步的逐条过滤；Step 3 触发时以本步的对齐规则为准。放开的理由：跨票累积的冗余只能靠动老注释来治，「只许合并」的窄口子治不了「上一票留下、本票没有对应新增」的那类冗余；而 Step 3 有可数的触发门槛、不是每次都跑，放开的面是有界的。

⚠️ **诚实边界**：闭卷重写同样是 LLM 概率判断、会误判——它把「漏看跨条重复」换成了「可能误删一条真 why」，**没有让注释质量变得可自动验证，一步都没有**。误删靠 Step 4 重测 + 判据三的保留清单兜；理想集合里凡属保留清单的（指令型注释、外部稳定链接）一律照抄，不进闭卷。

**Step 4 · 汇总核实 + 删完重测（主 agent）**
**核实以 `git diff` 为唯一事实源，不采信子代理的文字自报**（实测教训：子代理会编造报告——声称改了没碰的文件、虚构原文；自报只作线索、不作证据）。逐个子代理核：① 实际改动文件 = 分配给它的文件（**未分配文件应零改动**）；② **测试文件应零改动**（范围级排除的硬边界）；③ 非注释行改动——未触发 Step 3「搬」的文件应为 **0**；触发且做了机械搬的，其非注释行改动**必须逐一对应到 review 产物记录的搬迁项**，对不上即视为**不可信**（无论是越权还是仅漏记，都不采信）、回退——「回退」这个动作与「越权」这个诊断解耦,免得日后把漏记误判成违规。
核完再重跑 typecheck + lint + 该范围测试——删注释不该破坏任何东西；误删指令型注释（`eslint-disable` 等）在此暴露。
**记录进本 stage 的 review 产物**（分节结构由各 flow 自定，本 skill 只保证这些信息不因「子代理跑完就散」而丢，不规定产物内部排版）：① 删除条目逐条附反问答案（反问没有预言机、模型能敷衍「它不构成改错点」就照删，这份可审清单是唯一下界）；② 机械搬逐条（对应上面 git diff 第 ③ 条）；③ **未当场做的「搬迁候选」**；④ **Step 3 对齐若在某文件产不出任何合并/删除/新增**（常见于保留清单主导的文件）——不许默默略过，须写明「本文件对齐无变更，因现有注释已各自映射理想集合、无重叠」，逼子代理别拿「保留清单太多」当跳过闭卷的偷懒出口。

## 边界（诚实标注，不对上游夸大）

- **进程指代**：符号类有 grep 前哨、文字类靠 Step 2 语义——覆盖绝大部分，但形态无穷（任意文字指代都可能），**不保证 100%**，允许极少漏网。
- **跨文件重复的散文注释合不了**：并行安全规则（删「别处已记录」只认预言机）的代价是——两个文件各留一条讲同一件事的散文注释，**没有机制能把它们合并成一条**（判据三的「合并」只在同文件内、Step 3 也是文件级）。这是为消互删竞态付的确定成本，与「越少越安全」有轻微张力，**已知、接受**——宁可两处各留一条真 why，不冒并行双删把它删空的险。
- **保留清单主导的文件，Step 3 闭卷被架空**：当一个文件绝大多数注释都落进保留清单（如登出 / 会话编排那种整文件几乎全是结构性论证的），闭卷对齐没有可挑战的对象，Step 3 实质退化成逐条过滤——**同文件内两条都属保留清单的重复，这轮抓不到**。这是「保护 why」与「重建理想集合」的固有张力，**已知、接受**（Step 4 要求这类文件留痕交底、不许静默略过）；要治只能单独放开该文件的保留清单重跑 + 每处删除附反问 + 人审（机器审不了），默认不做。
- **"相对代码冗余" / "注释失效"**：**没有确定性工具**，是 LLM/人的概率判断（机器判准确率低），会误判——故默认保留四类 why、删完重测兜底。
- **为什么不做 fail-closed gate**：进程指代形态无穷（T / P / § / 纯文字都可能），固定 grep 既会**误伤**合法代码、又**不可能穷尽**真正的指代；判断本质是语义、该由本 skill 承载并**允许放行**，gate 化只会两头不是人（误伤阻断 + 仍漏文字类）。故本 skill 是**给 AI 的辅助判断 + 绝大部分兜底 + 允许误判放行**，不是机器闸。
- 能被自动验证的只有「搬进类型/断言/doctest」的部分；散文 rationale 的准确性最终只能靠人审。本 skill **大幅降低**噪声与腐坏面，但**不消除**验证不对称。
